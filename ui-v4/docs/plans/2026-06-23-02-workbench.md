# ui-v4 Plan 02 — Requests 工作台与 Live 列表稳定性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 把 Plan 01 的最小 Requests 列表升级为**主从一体工作台**：左侧 Live 泳道（常驻固定高度，WS 在飞请求）+ History 游标列表（缓冲横幅 + tail 暂停 + 选中粘滞），右侧按 URL 选中的请求 ID 独立拉取的详情占位；深链 `/requests/:id`。

**Architecture:** server-state（History 游标分页）用 TanStack Query `useInfiniteQuery`；client-state（Live 在飞集合、tail/buffer、选中）用 Zustand + URL。WS 扩展处理 `active_request_changed`（Live 泳道增删改）+ `connected` 初始快照 + `entry_added`/`entry_updated`（History，tail-on 合入 / paused 缓冲）。选中是 URL 驱动（`/requests/:id`），详情按 ID 独立 `fetchEntry`（不依赖行在不在列表窗口）。本计划详情只做**占位**（诊断摘要 + raw JSON），完整 C 布局留 Plan 03。

**Tech Stack:** 续 Plan 01（React 18 / TS strict / TanStack Query v5 `useInfiniteQuery` / Zustand / React Router 6 hash / Tailwind v4 / bun+vitest 双测试）。

参照：spec [../DESIGN.md](../DESIGN.md) §4（4.1 深链 / 4.2 列表稳定性）；后端 WS 契约 `src/lib/ws/broadcast.ts`（`active_request_changed` / `connected` / `entry_added` / `entry_updated`）；`ActiveRequestInfo` 形状见下。Plan 01 既有：`@/lib/ws-client`（模块单例+引用计数，dispatch 现处理 entry/stats 三类）、`@/lib/api`、`@/hooks/useEntries`、`@/stores/ui-store`、`@/components/requests/RequestsListPage`（本计划替换）。

## 后端数据契约（实证，勿猜）

- WS `active_request_changed` data：`{ action: "created" | "state_changed" | "completed" | "failed", request?: ActiveRequestInfo, requestId?: string, activeCount: number }`。
- `ActiveRequestInfo`：`{ id: string, endpoint: string, rawPath?: string, state: string, startTime: number, durationMs: number, model?: string, stream?: boolean, attemptCount?: number, currentStrategy?: string, queueWaitMs?: number }`。
- WS `connected` data：`{ clientCount: number, activeRequests: Array<ActiveRequestInfo> }`（初始在飞快照）。
- WS `entry_added` / `entry_updated` data：`EntrySummary`（已完成/持久化条目）。
- WS 无 subscribe 时收全部事件（已实证）。
- 详情：`GET /history/api/entries/:id` → `HistoryEntry`（in-flight-first 读，在飞请求也返回数据；reaper 淘汰 → 404）。

> **ActiveRequestInfo 类型落点**：现有 Vue 在前端 `ui/src/api/ws.ts` 定义了它。理想是后端 single-source，但后端当前未导出该 wire 类型为公开 type。本计划在 `ui-v4/src/types/ws.ts` **前端定义** `ActiveRequestInfo`/`ActiveRequestChangedInfo`/`ConnectedInfo`（WS 消息判别联合，属前端专有），并在文件头注释标注"待后端导出后改 re-export"。这是 spec §5「类型 single-source」的已知例外（wire 消息类型后端未公开），记入 Plan 05 待办。

```ts
import { create } from "zustand"

import type { ActiveRequestChangedInfo, ActiveRequestInfo } from "@/types/ws"

export interface LiveState {
  byId: Record<string, ActiveRequestInfo>
}

/** 纯 reducer —— 把一个 active 事件应用到在飞集合(不可变,返回新对象)。 */
export function applyActiveEvent(state: LiveState, ev: ActiveRequestChangedInfo): LiveState {
  if (ev.action === "completed" || ev.action === "failed") {
    const id = ev.requestId ?? ev.request?.id
    if (id == null || !(id in state.byId)) return state
    const next = { ...state.byId }
    delete next[id]
    return { byId: next }
  }
  // created / state_changed
  if (!ev.request) return state
  return { byId: { ...state.byId, [ev.request.id]: ev.request } }
}

interface LiveStore extends LiveState {
  apply: (ev: ActiveRequestChangedInfo) => void
  setSnapshot: (list: Array<ActiveRequestInfo>) => void
  reset: () => void
}

export const useLiveStore = create<LiveStore>((set) => ({
  byId: {},
  apply: (ev) => set((s) => applyActiveEvent(s, ev)),
  setSnapshot: (list) => set({ byId: Object.fromEntries(list.map((r) => [r.id, r])) }),
  reset: () => set({ byId: {} }),
}))
```

注：`ev.requestId == null` 用 `== null`？本项目 eqeqeq 禁 `!= null`。改用 `=== undefined`——但 requestId 可能是 string|undefined，且 request?.id 同理；写 `const id = ev.requestId ?? ev.request?.id; if (id === undefined || !(id in state.byId))`。请按 eqeqeq 调整（测试不变）。

```ts
import { create } from "zustand"

export interface ListState {
  /** 自动跟最新(tail-on);选中/上滚自动转 paused。 */
  tailOn: boolean
  /** paused 期间到达的新完成条目 id(去重,FIFO),点横幅/resume 时合入。 */
  bufferedIds: Array<string>
  /** URL 驱动的选中 id 的本地镜像(用于粘滞高亮;真值仍以路由为准)。 */
  selectedId: string | null
}

export const initialListState: ListState = { tailOn: true, bufferedIds: [], selectedId: null }

export type ListEvent =
  | { kind: "incoming"; id: string }
  | { kind: "flush" }
  | { kind: "resume" }
  | { kind: "select"; id: string }
  | { kind: "scroll-up" }
  | { kind: "reset" }

/** 纯 reducer —— 见 spec §4.2(三件套:Live 泳道/缓冲横幅/选中粘滞 + tail)。 */
export function reduceListEvent(state: ListState, ev: ListEvent): ListState {
  switch (ev.kind) {
    case "incoming": {
      if (state.tailOn) return state // tail-on:调用方直接 prepend,不缓冲
      if (state.bufferedIds.includes(ev.id)) return state
      return { ...state, bufferedIds: [...state.bufferedIds, ev.id] }
    }
    case "flush":
    case "resume": {
      return { ...state, tailOn: true, bufferedIds: [] }
    }
    case "select": {
      return { ...state, tailOn: false, selectedId: ev.id }
    }
    case "scroll-up": {
      return state.tailOn ? { ...state, tailOn: false } : state
    }
    case "reset": {
      return initialListState
    }
    default: {
      return state
    }
  }
}

interface ListStore extends ListState {
  dispatch: (ev: ListEvent) => void
}

export const useListStore = create<ListStore>((set) => ({
  ...initialListState,
  dispatch: (ev) => set((s) => reduceListEvent(s, ev)),
}))
```

```ts
import { useMemo } from "react"

import { useWs } from "@/hooks/useWs"
import { useLiveStore } from "@/stores/live-store"

/** 订阅 WS active/connected,把在飞请求维护进 live-store。挂在工作台一次。 */
export function useLiveRequests(): void {
  const apply = useLiveStore((s) => s.apply)
  const setSnapshot = useLiveStore((s) => s.setSnapshot)
  const callbacks = useMemo(
    () => ({
      onActiveRequestChanged: (info: import("@/types/ws").ActiveRequestChangedInfo) => apply(info),
      onConnected: (info: import("@/types/ws").ConnectedInfo) => setSnapshot(info.activeRequests),
    }),
    [apply, setSnapshot],
  )
  useWs(callbacks)
}
```

```ts
    queryKey: HISTORY_KEY,
    queryFn: ({ pageParam }: { pageParam: string | undefined }) =>
      api.get<SummaryResult>(`/history/api/entries?limit=50${pageParam ? `&cursor=${pageParam}&direction=older` : ""}`),
    initialPageParam: undefined as string | undefined,
    getNextPageParam: (last: SummaryResult) => last.nextCursor ?? undefined,
  })

  const callbacks = useMemo(
    () => ({
      onEntryAdded: (s: EntrySummary) => {
        dispatch({ kind: "incoming", id: s.id })
        if (tailOn) void queryClient.invalidateQueries({ queryKey: HISTORY_KEY })
      },
      onEntryUpdated: () => {
        if (tailOn) void queryClient.invalidateQueries({ queryKey: HISTORY_KEY })
      },
    }),
    [dispatch, tailOn, queryClient],
  )
  useWs(callbacks)

  // flush:点横幅时把 buffer 清掉并 refetch 合入(组件调 dispatch flush 后,这里失效)
  const bufferedCount = useListStore((s) => s.bufferedIds.length)
  useEffect(() => {
    if (tailOn && bufferedCount === 0) void queryClient.invalidateQueries({ queryKey: HISTORY_KEY })
  }, [tailOn, bufferedCount, queryClient])

  const entries = useMemo(() => (query.data?.pages ?? []).flatMap((p) => p.entries), [query.data])
  const total = query.data?.pages[0]?.total ?? 0
  return { ...query, entries, total }
}
```
> **合入策略说明**：tail-on 时新 entry_added 直接失效首页查询(TanStack Query 重取第一页含新条目);paused 时只记 buffer(`incoming` reducer 缓冲),列表冻结不动;用户点横幅 → 组件 dispatch `flush`(tailOn 变 true + buffer 清空)→ 上面 effect 触发失效合入。简化于"手动 prepend",换取正确性与不抖动(YAGNI:不做乐观 prepend)。
