## ⚠️ 待对齐项技术细节

### 1. `anthropic-beta` 合并

**当前行为**：`src/lib/anthropic/request-preparation.ts:53-64` 中 `buildAnthropicBetaHeaders` 返回的 `anthropic-beta` 直接 spread 到 headers，**没有读取客户端原始请求头**。

**修复方向**：

```typescript
// 伪代码：在 prepareAnthropicRequest 入参中接收客户端原始 headers
const clientBeta = clientHeaders['anthropic-beta']  // 可选
const localBeta = buildAnthropicBetaHeaders(model, opts?.resolvedModel, {...})
const merged = mergeBetaHeaders(clientBeta, localBeta['anthropic-beta'])
// merged: Set 合并去重，可选做 allowlist 过滤防止未知 beta 被上游拒绝
```

**验证**：
- 先搜 History 是否有来自客户端的 `anthropic-beta`（大多数 Claude Code 流量应为无）
- 若有，引入合并后做端到端测试

### 2. OpenAI Responses `reasoning.effort` guard

**当前行为**：Responses handler 透传客户端的 `reasoning.effort`，不做模型能力校验。

**观察维度**：
- `claude-haiku-4.5` 经 `/responses` 路径且带 `reasoning.effort` 会不会 400？
- History 中 `invalid_reasoning_effort` 错误是否**只**出现在 Anthropic Messages 路径？

**若确有真实失败**：
- 仿 `learnEffortsFromError` 做 OpenAI 版本，或
- 在 `openai/request-preparation.ts` 加预检：`resolvedModel.capabilities.supports.reasoning_effort?.length` 为空时剥离 `reasoning.effort`
