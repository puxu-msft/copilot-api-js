## 2. 两个 CRITICAL 共享 driver 契约缺陷（RFC §11 已裁决，复核时**重点重验**，实现时 **C0 先做**）

这两个是 RFC 最大价值——影响**所有格式**、CC 从没暴露、直接实现极难发现：

### C0-① driver 返回 pre-retry env（RFC §11.1）
`driver.runRequest` 返回 `{ok, upstream, env: rewritten}`（pre-exchange env）；`runExchange` 内部 `current = action.env` 但只 `return upstream`，**最终 post-retry env 从不返回**。CC/Gemini/Responses 潜伏无症（只读 `env.body.model`，不被任何策略改）；**Anthropic 会爆**——pump 读 `env.body.tools` 建 recoverer 的 toolNames/toolSchemas，而 `deferred-tool-retry` 改 `tools` → retry 后 stale → forwarded 流字节差异。
**修复（C0）**：`runExchange` 返回 `{upstream, env: current}`（post-retry）；`runRequest` 返回该 env。回归测试：deferred-tool retry → forwarded 流 recoverer 见 un-defer 工具名。**核验现有 4 格式套件不回归**（它们 result.env 只读 model/stream/targetEndpoint/ctx，retry 不改这些）。

### C0-② onResolved 无 meta 通道（RFC §11.2，机制已更正）
`EnvRetryStrategy.onResolved(env)` 仅收 env、无 meta；env-`RetryAction` 也**无 `.meta` 字段**（adapter 的 legacy `action.meta` 只在 handle 闭包内经 `onMeta` 即时发射）。driver 路径上 `unsupported-beta-retry.onResolved` 读不到 `meta.probedBetas` → **跨请求 beta 学习静默失效**。且 adapter 的 onMeta 在 budget gate **之前** fire → budget-rejected retry 污染 pipelineInfo（幻象 truncated/beta-stripped）。
**修复（C0）**：**widen env-`RetryAction` 的 retry 变体携带 `meta?`**——adapter 把 legacy `action.meta` 设到返回的 env-action（不再 handle 内即时 onMeta）；driver 在**接受 retry 后**（gate 之后）把 `action.meta` 存 loop-local，① 透传 `onResolved(env, meta?)`（widen 签名）② 发 onMeta sink（仅 post-gate）。**failing-first 测试**：interleaved + budget-rejected 序列，断言 unsupported-beta.onResolved 经 driver 收到正确 probedBetas + fixate cache + budget-rejected 不污染 pipelineInfo。
> truncateResult（CC/Anthropic 的 marker）走同一 onMeta 通道——也须 post-gate 发射。

## 5. 关键坑 / 教训（前序格式 + RFC review 已踩，照搬）
- **C0 先做**：两个共享 driver 契约 bug 必须先于 Anthropic 接线修，且核验 4 格式不回归。
- **不改 byte-critical pump 逻辑**：`processOneStreamEvent`/`forwardToClient`/heartbeat/recoverer/decoder/server-tool-filter/thinking-sig-shim 复用、不改；只把流源从 `processAnthropicStream` 换成 driver.runResponse + 内联 parse+accumulate+break。transport 的 `guardSseIterable` 与 `processAnthropicStream` 的 guard 语义已核验等价（同抛 StreamShutdownError/StreamClientAbortError）。
- **terminal error SSE**：upstream mid-stream `error` 事件被 accumulate（设 `acc.streamError`）+ **forward 给客户端（恰一次，经同一 processOneStreamEvent）** + break；loop 后 `acc.streamError ? fail : complete`。CC 无此路径（OpenAI 终态错误是 throw）——必须专测。
- **catch 路径 flush**：mid-stream 失败时错误帧**之前** flush recoverer + decoder（否则半构建 tool_use 被腰斩）。
- **preprocess 两步 disjoint**：`preprocessAnthropicMessages`（message-level，route 跑、喂 web_search preprocessInfo）≠ `runAnthropicRequestRewrites`（tool+sanitize，codec 跑）。**无双重 preprocess**，无 skip-flag。
- **message-mapping baseline** = `codec.getTruncateBaseline()`（preprocessed、pre-initial-sanitize），**非** client-raw originalSnapshot。
- **betaProbe 时序**：codec 在 prepareWire 后 `recordOutbound`（每 attempt），strategy 失败后读 candidates——1:1 对齐 legacy，无 off-by-one。
- **失败 settle**：driver 抛错时 ctx 可能悬挂——codec 暴露 `getContext()`，handler 所有失败分支 settle（setHttpHeaders + fail）+ `c.set("requestContext")`。reject 路径产 `failed` entry（中间件 `completeFromHttpStatus(400)` 收尾，**非悬挂**；`createFullTestApp` 缺中间件的 harness 才显 pending——与 CC/Responses/Gemini 一致，非新问题，详见 05-progress P2.4-D3）。
- **测试隔离**：DI/fetch-mock，**不用 `mock.module`**；mutate 全局 state 用 `autoRestoreState()`/afterEach 还原；fs I/O 用注入临时目录，**绝不碰真实 `$HOME`**；afterEach **还原 flag 默认值**（不硬编码 false，CC 踩过的泄漏坑）；测试环境 `disabled_models` 陷阱——每请求前 `setDisabledModels([])` + 重 `setModels`。
- **flaky/时序**：fake timers + mock 随机/时钟；连跑 10-25× 确认确定性（跑 3 次碰巧全过 ≠ 修好）。
