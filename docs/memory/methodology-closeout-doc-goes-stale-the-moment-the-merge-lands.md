**收尾文档里凡是描述「接下来要做 X」的断言，在 X 真的发生之后就是错的**——而它恰恰是在 X 发生前写的，写的时候完全正确。2026-08-08 无损 shutdown 整改：终态报告、plan 状态头与两份评审记录共八处写着「整改尚未合回 master、待合并」，用户执行合并（`ad8128ad`）之后这八处同时变成假的，而没有任何东西会提醒我回来改。

**Why:** 这类错误有三个让它特别难被自己抓到的性质：

1. **它不是写错，是「写对之后世界变了」。** 通读全文查不出来——通读只能确认「我写出了我想写的」（`reread-docs-after-writing` 的边界），而这里我想写的当时就是对的。
2. **触发它的动作由别人执行**，所以我这边没有任何事件可挂。用户回一句「已合并」是唯一的信号，很容易被当成「那我可以收工了」而不是「有八处要改」。
3. **它伪装成完成态。** 文档通篇在讲「已完成、全绿、已闭合」，中间夹一句「待合并」，读者会自动把整份读成完成件，然后**不去执行那个 X**——本轮的独立评审正是据此判 blocker：读者据「已合入、可合并」不会再合并，而 master 上此刻仍带着两条 MAJOR。

**How to apply:**

- **触发条件（不限于「我本轮写下的」，也不需要用户开口）：** 任何收尾事实发生**或被你察觉已经发生**时都要跑一遍——合并、部署、发布、分支删除、依赖升级落地皆算。触发不依赖用户说「已合并」：`git merge-base --is-ancestor <sha> master` 退出 0 就是同一个信号，自己也能测出来。**继承来的断言同样在范围内**——本轮四份**别人写的**记忆／plan 仍称「待合并 master」，而其提交（`30a483df`、`8e0376d4`、`2a77bf7c`、`bd3aafe0`）早已在 master；它们不是我写的，但每次加载都在误导人，一样要改。
- **登记要有载体，不能只是「记住」。** 写下「待/尚未/下一步是 X」的同时，在本轮的收尾产物（终态报告或临时清单）里开一节列出：**目标事实 X、谁去做、复核命令、携带该断言的文件清单、闭合标记**。没有这五样，「当场登记」就退化成一句自我承诺——而承诺不会在 X 发生时提醒任何人。
- **别只改叙述，要把判定翻面成正向可复跑命令。** 反例（改坏的形态）：把「待合并」删掉、写成「已合并」——读者仍然只能选择相信。正确形态是给出会随事实变化的命令：`git branch -a --contains <fix-sha>` 应当同时列出 `master`，`git show master:<file> | grep <invariant>` 应当看到修复后的形态。**判定命令的方向也要一起翻**——本轮我一度把「只输出本分支即未合并」原样留着，那句话在合并后自己就是错的。
- **扫描按语义载体走，关键词只是入口，且零命中不等于完备。** 本轮八处分布在四个文件；我用「待合并｜尚未合回｜未合并回」扫完、以为干净了，随后扩到「需用户执行」这类**转述性**说法才抓到第九处（它描述的是另一份文档的状态、不含任何「尚未」字样）；**独立评审又在同一 commit 上找到第十处**（提交谱系表里的「仍只在本分支」——同样不含任何被我扫过的关键词）。所以：①除断言本身，还要扫对它的**转述与指路**；②命中后**逐条 disposition**，活断言归零、历史引文与讲事故的正文（比如本条）标注后可留；③**扫完不是证明**——真正的判据是「凡描述该事实的位置都已过一遍眼」，关键词只帮你找到大部分。
- **描述「本文档／本批改动自身」合并状态时，别写无时间锚点的静态结论，改给判定命令。** 这是本条的边界情形。**注意它的准确形状**：一句不带时间锚点的当前状态断言（「本批仍待合并」）**无法跨合并前后都为真**——这是跨状态的不变量失败，**不是**「改不完」。写「已合并」只在合并落地前短暂为假、之后永久为真且不再需要新提交，所以**只要求最终 master 上的文本正确，一轮就收敛**。
    因此推荐判定命令的理由不是「唯一出口」，而是**它更稳**——静态文本不适合充当动态状态源，而命令会自我更正：
    ```
    git -C <repo> merge-base --is-ancestor <branch> master && echo merged || echo pending
    ```
    判据（两次收窄后）：
    1. **锚点要不可变，不是「有时间词」。** 「截至今天」照样漂移；只有**绝对日期或 commit SHA** 能把命题钉死。
    2. **「本批」必须是可枚举的 commit 集，否则不可机械判定。** 判定方法：**句子所指的 commit 集，是否包含承载这句话的那个 commit**——包含即自指、换判定命令；不包含即外指、照常写事实 + 复核命令。**集合没冻结就一律用命令。**
        这不是理论顾虑：本轮文档里的「这批更新需要再合一次」正是中间情形——「这批」若含写下它的那次提交就是自指，若只指前文列举的既有提交就是外指，两种读法都成立，读者无从分类。
    3. 描述**别的东西**的状态（某个 fix 在不在 master、某特性有没有 landed）不受本条约束。
    **我第一版把这条写成了「存在无穷回归、改不完、唯一出口是判定命令」，被独立评审当场证否**——那是把「静态断言无法跨状态持续为真」误述成「修订序列必然无限」。留在这里当反例：**结论对（该用命令）不代表理由对**，而错误的理由会把一条本可精确的判据撑成过强的全称命题。第二版又被同一位评审指出「本批」边界未定义、仍不可机械判定——**一条判据可以方向正确、措辞收窄，却依然因为一个未定义的集合名词而无法执行。**
