写下任何**顺序前置**（「X 必须晚于 Y」「Y 未完成前不得 X」）之前，先追一遍它的**完整触发／放行链**，**再按门的类型**判它成不成立。

**关键动作是先分型。** 顺序门有两种合法的闭合形状，**它们的成立条件不同**，拿其中一种的条件去要求另一种，必然误判——我在这条判据上就先后翻车三次（见文末「判据自身的翻车史」）。

## 形状 A：状态门（放行时读 Y 的当前状态）

放行方在放行点读取 Y 的谓词并据此决定。成立条件：

1. **每个 X 入口**的放行都**控制依赖**于该谓词——即 Y 的读取结果**支配**（dominate）放行动作。机械判法：沿每个 X 入口的数据／控制流看，Y 的结果是否真的决定了放行；**只读不判的旁路 observer 不算**。
2. 该谓词**权威**且在**放行点仍然有效**。**「权威」按可验证的一致性契约定义，不按物理载体**：只要该来源的契约足以裁决 Y，或其值可追溯／校验为权威状态并满足所需的一致性与新鲜度，就算权威——线性一致读副本、受 lease 保护的 materialized state、带 generation／version 且在放行时校验的快照都合格。要拒绝的是**未经验证、可能滞后的副本或摘要**，不是「副本」这个载体本身。
3. **Y 不满足、或 Y 读不到时必须阻断**（fail-closed）。读取失败即放行等于没有门。
4. **消除 check-and-act 竞态**：原子 check-and-act、lease／generation token、锁，**或 Y 单调**（`Y-has-occurred` 一旦为真不回退——此时陈旧读只会说「还没完成」而误阻断，不会误放行，故不需要原子性）。

## 形状 B：因果／capability 门（Y 成立才产生放行凭据）

Y 的权威 owner 在完成后签发 permit／event，X 由消费该凭据触发。**此型不要求 X 在放行时再读 Y 的真相源**，因为顺序已被因果能力编码。成立条件：

1. 该 permit／event **只可能由 Y 成立而产生**。
2. **不可伪造、不可从旁路取得**。
3. **每个 X 入口都必须消费它**——存在一条不消费凭据就能触发 X 的入口，此型即不成立。
4. Y 可能回退时，凭据须不可重放（Y 单调则不需要这一条）。

## 两型共同的验收（缺一条就只是把愿望挪了一层）

⚠️ **前提：双控必须隔离目标门。** X 往往有多个前置（Y、Z、W…），**不能假定 Y 是 X 的充分条件**（它可能是，但那要证明，不能默认）。不隔离就会两头出错：正控写成「Y 完成 → X 放行」会**误杀合法的多前置门**（Y 过了但 Z 未批，X 本就该被挡）；负控只看「X 没发生」会**放行假门**（阻断可能全由 Z 造成，一个根本不读 Y 的假门照样通过）。

- **负控**：保持其他前置**满足不变**，只翻转 Y 为未完成 → X 被阻断，**且须核对阻断的 provenance 确实来自目标 Y 门**，不是兄弟门代咬；
- **正控**：Y 成立**且所有其他独立前置均满足**时，**目标 Y 门不再阻断 X**（措辞是「这道门不再挡」，不是「X 一定发生」）；
- **入口全集**：枚举所有 X 入口，逐个验证无旁路——**这是两型都最容易漏的一条**；
- **失效对照**：只破坏**目标** gate／permit（A 型喂陈旧值或让谓词读取失败，B 型伪造或抽掉凭据），判据必须**变红**，且**失败位置或 provenance 要命中目标机制**——只看「最终 X 没发生」同样会被兄弟门代咬。

**「我实测过它生效」不算数**——happy-path 探针没有判别力。

## 判定「两型都不成立」之后

首选**让 X 提前发生也无害**（消门，而不是加固门）。本轮做法是把长期价值**先行**落进已提交的持久接收者，于是清理何时发生都不删唯一副本；`master` ancestry 只保留它真正管得住的职责——「可宣告集成完成、可清理 branch/worktree」。首选它是因为它不依赖任何外部机制持续正确。次选是**按 A 或 B 真正建一个门**，并走完上面的验收。

**本轮实例（2026-08-08，History Worker Batch 1b 收尾）**：我把「临时证据清理必须晚于收尾提交进入 `master` 祖先」写成清理前置。分型后两型皆不成立——A 型：清理由 **Claude job 自动回收**触发，没有任何一环读 ancestry 并据此决定放行；B 型：「提交进 master」不产生任何清理凭据，会话正常结束、崩溃或平台回收都能独立触发清理。终审 reviewer 判 major，改走「消门」。

**两个放大这个错误的形态**：
- **逐行复述**会让它看起来像已有 disposition。本轮那条失效的门被清单**逐行复述了 56 遍**，单看任一行都完整合规，只有回到「分型追链」这一步才暴露。
- 它是**判据之间留缝**而非某条判据写错：盯「产物有没有进提交」的检查（当时 `session-closeout` 自验表的 V7；该 skill 2026-08-08 已并入 `closing-a-development-session`，其 verification-log 的 V 编号自 V1 重新起算）**结构性地**看不到「我设的前置条件在物理上能不能被执行」。逐条核判据核不出来。

**Why:** 不可控的平台生命周期事件（job 回收、容器重建、缓存过期、CI 超时终止）被当成受控步骤来排序，是一类会静默失效的设计错误——它在纸面上完全自洽，只在真正发生时丢数据，而那时已经没人在看。

**判据自身的翻车史（这段比结论更有用）**：同一条判据被独立 reviewer 连打四轮，**每轮错的方向都不同**。①收在「X 的**直接执行者**读不读 Y」→ false-red，误杀合法因果门；②放松成「链上**有谁读过** Y」→ false-green，放行旁路只读日志／陈旧读取／fail-open／入口绕过四种；③写成**四条全局合取** → 又 false-red，把状态门的「读权威真相源 + 原子」强加给 capability 门；④分型解决了前三轮的来回，但**共同双控仍未隔离目标门**——正控「Y 完成→X 放行」误杀合法多前置门，负控只看「X 没发生」则被兄弟门代咬，连不读 Y 的假门都能通过；同轮还把「权威」按**物理载体**定义（排除一切副本／摘要），误杀线性一致副本与 lease 保护状态，且与自己后文承认 lease／generation 合法自相矛盾。

**两条可迁移的判据**：
- **一条判据若在复审中反复朝相反方向被打回，先怀疑它管了不止一类对象，去分型，别继续调措辞**（前三轮的根因）。
- **双控必须隔离目标机制**：被测对象有多个前置时，「翻转 Y 后坏事没发生」既可能是目标门起了作用，也可能是兄弟门代咬；不固定其他前置、不核对 provenance，正负控都没有判别力（第四轮的根因，与本仓 [[methodology-verify-the-mutation-actually-applied]] 同源）。

**How to apply:** 每写一条顺序前置，当场①**声明它是 A 型还是 B 型**（都不是就直接走消门）②按该型的条件逐条给出答案③对两型共同验收的四项各给出可判别结果。此形态已记入 skill `session-closeout` 的 `verification-log.md` 2026-08-08 节，标为「新增负样本、建议入表」，待独立评审决定是否升为正式自验条目——**未经评审不得自行改写 SKILL.md 正文**（instruction text 必评）。
