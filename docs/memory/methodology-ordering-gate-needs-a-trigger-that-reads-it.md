写下任何**顺序前置**（「X 必须晚于 Y」「Y 未完成前不得 X」）之前，先追一遍它的**完整触发／放行链**，然后按下面四条判它到底成不成立。

**门成立的条件是「控制依赖」，不是「有谁读过 Y」**（这两者差一个数量级，我在两轮整改里先后写错过两次）：

1. **每个 X 入口**的放行都依赖一个**权威且新鲜**的 Y 谓词——「权威」指该谓词就是 Y 本身的真相源而非它的副本或摘要，「新鲜」指读取点与放行点之间 Y 不会翻转。
2. **Y 不满足、或 Y 读不到时，X 必须被阻断**（fail-closed）。读取失败就放行（fail-open）等于没有门。
3. **检查与放行原子**，或有等价的失效机制。**这一条答「否」就直接判红**，不是记录一下就算过。
4. 走**因果事件**方案（Y 完成才产生 X 的触发事件）时，还须证明**该事件只会在 Y 成立后产生**，且**不存在替代触发路径**。

⚠️ **四种最常见的蒙混形态，逐个排除**：①**旁路读取**——某个 observer 读了 Y 但只用于日志，放行方仍无条件放行；②**陈旧读取**——读的是 Y 的缓存／快照，放行时早已过期；③**fail-open**——gate 自身失败时默认放行；④**入口绕过**——枚举不全，另一个 X 入口根本不经过这个 gate。**「链上确实有人读了 Y」对这四种全盲。**

⚠️ **判据是整条链，不是 X 的直接执行者。** 直接执行者不读 Y，门仍可能成立（因果事件或 scheduler／hold 承担了控制依赖）。把判据收在直接执行者上会**误杀正确设计**（false-red）——这是我第一轮写错的方向；而把它放松成「有谁读过 Y」则会放行上面四种蒙混（false-green）——这是第二轮写错的方向。**两个方向都要防。**

**本轮实例（2026-08-08，History Worker Batch 1b 收尾）**：我把「临时证据清理必须晚于收尾提交进入 `master` 祖先」写成清理前置。追链后确认**没有任何一环对清理构成控制依赖**——清理由 **Claude job 自动回收**触发，会话正常结束、崩溃或平台回收都会触发它；没有 scheduler 读 ancestry，也没有任何机制让「提交进 master」去产生清理事件。终审 reviewer 判 major。

**判定「不是门」之后有两条合法出路，别只记住第一条**：
1. **首选：让 X 提前发生也无害**（消门，而不是加固门）。本轮做法是把长期价值**先行**落进已提交的持久接收者，于是清理何时发生都不删唯一副本；`master` ancestry 只保留它真正管得住的职责——「可宣告集成完成、可清理 branch/worktree」。首选它是因为它不依赖任何外部机制持续正确。
2. **备选：建立一个真正构成控制依赖的外部 gate**（如可显式 hold 生命周期的机制）。这条合法，但**验收必须双控且穷尽入口**，「我实测过它生效」不算数：
   - **负控**：已知 Y **未**完成时，X 确实被阻断；
   - **正控**：已知 Y 完成时，X 确实放行（防 false-red）；
   - **入口全集**：枚举所有 X 入口，逐个验证没有旁路；
   - **失效对照**：让该 gate 失败、或喂它一个陈旧 Y 值，判据必须**变红**。
   缺任一条，就只是把同一个愿望挪到了另一层。

**两个放大这个错误的形态**：
- **逐行复述**会让它看起来像已有 disposition。本轮那条失效的门被清单**逐行复述了 56 遍**，单看任一行都完整合规，只有回到「追触发链」这一步才暴露。
- 它是**判据之间留缝**而非某条判据写错：盯「产物有没有进提交」的检查（skill `session-closeout` 自验表 V7）**结构性地**看不到「我设的前置条件在物理上能不能被执行」。逐条核判据核不出来。

**Why:** 不可控的平台生命周期事件（job 回收、容器重建、缓存过期、CI 超时终止）被当成受控步骤来排序，是一类会静默失效的设计错误——它在纸面上完全自洽，只在真正发生时丢数据，而那时已经没人在看。

**How to apply:** 每写一条顺序前置，当场把**完整触发／放行链**标注出来，并对上面四条成立条件逐条给出答案（哪个入口、依赖哪个 Y 谓词、Y 读不到时阻断还是放行、检查与放行是否原子）；同时对四种蒙混形态逐个排除。整条链上没有构成控制依赖的一环，就走上面两条出路之一，优先消门。此形态已记入 skill `session-closeout` 的 `verification-log.md` 2026-08-08 节，标为「新增负样本、建议入表」，待独立评审决定是否升为正式自验条目——**未经评审不得自行改写 SKILL.md 正文**（instruction text 必评）。
