写**给未来的自己看的判据**（skill／rule／验收条款）时，我的错误高度集中在**同一族**：**门写出来了，但没有任何东西会去执行它**。2026-08-08 写 `session-closeout` §3b/§4 时，一份 skill 段落被独立 reviewer 连打六轮，其中 **2 个 blocker、十余条 major**，而它们几乎全是这一族的不同形态：

| 形态 | 当时写成了什么 | 为什么不成立 | 可观察修法 |
|---|---|---|---|
| **裁决点不可达** | 「provisional 候选交 §1 裁决」 | §1 排在 §4 **之前**、那一轮早已跑完，没有东西会回头执行 | 指定一个**流程上尚未越过**的时点，并明写「不得拿之前那次的结论顶替」 |
| **自证空结果** | 「没有候选时免评审」 | **恰恰是漏掉候选的那一轮才会得出空清单**，免评审刚好跳过唯一的独立检查 | 空清单同样送审，且**空是一条待核断言**而非豁免 |
| **评审无 oracle** | 把自述清单送审 | reviewer 看不到父会话事件源，审的是我的叙述不是事实 | 一并交出**可独立枚举的事件源**，要求它先自行枚举再**双向对账**；拿不出就标「仅形式复核」 |
| **判定了却没有回路** | 「审出承重证据」 | 只写了判定，没写判定之后回到哪一步，流程带着结论继续走到删除 | 明写**回流到哪个步骤**，并让先前的评审结论**作废、须重审** |
| **按对象类型分叉** | 回流只覆盖「tmp 文件被判承重」 | 漏掉「非文件候选被判需持久化」那一路 | 用**状态变化**（disposition 变了）驱动，别用**对象类别**驱动 |
| **不可逆动作 fail-open** | 无独立 oracle 时只「标注形式复核」 | 却没禁止它以 0 major 放行删除 | 不可逆动作一律 **fail-closed**：判别力为零时取保守侧 |
| **顺序写反** | 先删 tmp、后做候选发现 | 发现承重时内容已没了，后置评审救不回 | 不可逆动作排在**所有发现步骤之后**，并在两侧互相声明 |
| **声明单源、实际双判** | 「裁决权单归 §3b」，但 §4 里仍留着一条「值不值得写」的门 | 两处各判，同一份证据可能在一处判可删、另一处判必写；且**非文件候选填不进文件专用 schema**（没有绝对路径／字节／清理前置），所谓「送回去处置」根本执行不了 | 把**通用字段**抽成一份，文件行在其上**追加**专用字段；另一处只产候选、不设门 |
| **无边界 + 入列前自评过滤** | 先是「逐条过这四类」而无候选来源边界，后又用「无法廉价重建」在入列前筛掉一批 | 前者会退化成全量盘点；后者是**作者在评审看到它之前就把它删掉了**——评审永远不知道有过这一项 | 候选来源**限定为本轮可枚举事件**；入列判据只用**可观察事实**，「值不值得」留给评审，宁可多列 |

**Why:** 这些错在纸面上都完全自洽——每一条读起来都像一道门。它们的共同点是**我只写了「应该怎样」，没写「谁会在什么时刻去执行它」**。而指令文本的错误不会在测试里变红，它**静默地作用于此后每一次加载**。

**最尖锐的一次实证**：新写的「必须交出事件源 + 双向对账」条款**首跑就咬到了作者本人**——我交出 transcript 后，reviewer 独立枚举，发现我只列了 2 项候选，**漏掉了同一会话里被逐条打回的一整批**（伪「两轴」、不可达裁决点、自证空清单、过严 clean gate、先删后审、缺回流、无 oracle），而它们正是我自己刚写下的「被否掉的路线／被纠正过的因果」这两类的教科书样本。**作者对自己刚犯的错最没有距离感**，所以自述型清单必须配独立枚举，否则那份清单只证明「我记得我记得的」。

**而且它咬了两次。** 我据首轮结果补成 10 项后再送对账，reviewer 又指出**仍漏两格**（本表最后两行：声明单源实际双判／无边界+入列前自评过滤），并证否了我「第 4、6 类无新增」的自称——第 4 类实际新增了 job tmp 人口口径与 `fd` 枚举陷阱，第 6 类的多组 Git／GNU patch 探针直接驱动了裁决。**两次都是我以为已经列全了。** 这说明双向对账不是一次性仪式：补全之后仍要再对一次，直到 diff 为空。

**另一个方向的错也犯了两次**（别只防第一个）：判据写**过严**同样有害——「`--ff-only` 前要求 status 干净」误杀了「不重叠的 staged dirt 不妨碍快进」这一正确状态，而共享树几乎永远有别人的 WIP；「四条全局合取」误杀了合法的 capability 门。→ [[methodology-ordering-gate-needs-a-trigger-that-reads-it]] 记录了同一条判据在两个方向来回摆四次、最终靠**分型**才停下的完整过程。

**How to apply:** 每写下一条门，逐个回答四问：①**谁**在**哪个时刻**执行它（那个时刻在流程里还没过去吗）？②它判「否」之后，**回到哪一步**，先前的结论**作废吗**？③判定它需要的输入，**执行者当时拿得到吗**（拿不到就是没有 oracle）？④它保护的动作**可逆吗**——不可逆就必须 fail-closed。答不上任一问，那不是门，只是愿望。
