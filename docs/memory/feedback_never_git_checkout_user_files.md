唯一判据是**可恢复性**——任何可能销毁工作的操作前,只问一句:"若这步错了,还能不能恢复?"

**唯一硬约束**:会丢失 **git 救不回的工作**的操作绝不做——即**未提交/未暂存的修改**与**未追踪的文件**(从未进 git)。这类内容一旦被覆盖/丢弃,不可逆、无备份。

**不要把纪律记成一张"禁用命令清单"。** 真正危险的破坏性操作由 **harness 权限系统**在执行点拦截、向用户征求批准——那是命令层的把关。我要守的是上一层的**判断**:即便某操作被权限允许,只要它会销毁不可恢复的工作就不做;反之,只要后果可恢复(已提交的干净状态、git 历史在),被允许时就正常做,不必自我设限。所以重点**始终落在"可恢复吗",而非"这是不是删除/是不是某个命令"**。

落地:
- **可恢复 → 可做**:删除一个**干净的已追踪文件**(git 历史可完整恢复),用户**明确要求**时可做(先确认它无未暂存改动);但绝不自作主张删,绝不删未追踪文件。
- **不可恢复 → 绝不做**:覆盖/丢弃带未暂存改动的文件,或销毁未追踪文件。撤销我自己刚做的编辑,用**重新编辑**达成、而非回退操作(回退分不清我的改动与用户的)。

**Why(两个同源的错误):** ① 我曾撤销一次部分编辑时,没注意目标文件已有用户的未暂存工作,把它静默清除——不可逆、无备份;这奠定了"未提交=不可恢复=绝不销毁"。② 我又把它**过度推广**成"绝不删任何源文件、没有理由豁免",连用户明确要求删的可恢复文件也拒(把 over-coverage 测试文件强行"转换"而非删)。两个错误同源:**该看的是可恢复性,不是"是否删除 / 是否某条命令"**。
