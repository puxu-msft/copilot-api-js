在自然边界(一个 phase 收尾、会话结束、任务交接)**主动**做两件事,不等用户开口:
1. **提炼**:这段工作有没有可复用的经验/教训/反模式?凡有通用价值的都可固化为记忆(按 [[feedback-knowledge-routing-docs-vs-memory]] 判归属)。
2. **维护既有库**:沉淀新记忆时顺手体检整库——**陈旧→修**(引用过时、机制已变)、**近义→互链**(`[[...]]` 连起来,别让相关经验散落)、**冗余→删**。

**关键纪律:判断既有记忆是否已覆盖某条时,读它的正文,别只看索引钩子。** 索引(MEMORY.md 一行)是压缩过的,会掩盖"写窄/写偏"——曾据钩子判"已覆盖",实读正文才发现只截了半边(如 printwidth 记忆只讲代码、漏散文;real_problems 把"代码一致性"误归"纯主观跳过")。

**Why:** 经验不在边界提炼就蒸发;库不主动维护就腐烂成互相矛盾的旧快照。提炼 + 维护是记忆系统的周期性"垃圾回收",不是一次性。

**How to apply:** 边界时跑一遍:有无新教训 → 沉淀;碰到的相关旧记忆 → 实读正文比对,该修/该链/该删就做。本轮"从别处带来的 memory 合并审查"本身就是一次 distill。与 skill `empirical-verification`(核验)、[[feedback-completion-updates-docs]](doc-sync)同属收尾纪律。
