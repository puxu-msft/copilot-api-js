捕获知识时先判归属,别两处重复:
- **已完成 + 已有结论 + 项目特定**(架构决策、API 变更、机制说明、runbook)→ 写进**项目常驻文档**(docs/DESIGN.md、README、各模块文档等)。
- **未完成 + 可复用 + 通用原则**(跨项目适用的工作方式/教训/反模式)→ 写进**记忆**。
- 当前任务本身已产出相关 docs 或代码注释时,**不要**再在另一处重复同一信息。

**Why:** 记忆与文档职责不同:记忆是跨会话的"我该怎么工作 / 这个坑长什么样",文档是项目自身的事实与决策。错放会导致——通用教训埋进某项目文档里跨项目失忆,或项目事实塞进记忆里腐烂误导(记忆反映写入时的真,代码演进后不更新)。原则11 只划 **CLAUDE.md / 文档** 一刀;本条把同一精神**延伸到记忆 / 文档**这条 CLAUDE.md 未覆盖的轴(原则11 不管记忆系统该放什么)。

**How to apply:** 写之前问两点:(1) 这条只对本项目有意义,还是换个项目也成立?只对本项目 → 文档;通用 → 记忆。(2) 这是已尘埃落定的结论,还是仍在演进/待办?已定且项目特定 → 文档;待办/可复用 → 记忆。没有明显文档落点时,先问用户再新建顶层文件(呼应 [[feedback_no_unilateral_action]])。与 [[feedback-completion-updates-docs]]、[[feedback-distill-lessons-at-boundaries]] 配套。
