**收尾阶段写的汇总性表述，系统性地强于它们背后的证据。** 2026-08-08 无损 shutdown 整改的收尾里，我连犯五次，**没有一次是自己发现的**——全部由独立评审抓出：

| 形态 | 实例 | 它错在哪 |
|---|---|---|
| **数字来自记忆，没有 selector** | 「架构与 discovery guards 34/34」 | 从没有一条命令能产出 34。实测是 17 文件 178 pass |
| **汇总压缩掉了真实计数** | 「四路独立评审 0 blocker / 0 major」 | 实施三轮确实 0/0，但收尾两轮各报 1 blocker / 2 major。汇总把「全部已处置」写成了「从未有过发现」 |
| **描述自己刚做的动作也会写反** | 「整改已合入 master」 | 方向反了——我把 master 合进了分支，反方向没做。**口径**：按「被删除或改写的、含『待合并／尚未合回／仍只在本分支』的行」计，本任务自有文档 8 行（`9c323128` 6 + `f31d2bdd` 1 + `a47d9e11` 1），另有 4 组同类陈旧状态属**别的任务**的文档。先前本行写「十处」，那个数字没有口径——**这条记忆自己也犯过它警告的错，留作实例** |
| **推理被当成证明** | 「自指状态断言存在无穷回归、唯一出口是判定命令」 | 写「已合并」一轮就收敛。真正不可能的是让无锚点断言跨状态持续为真——那是不变量失败，不是修订序列无限 |
| **判据里的集合名词没定义** | 「描述**本批**自身状态时改用判定命令」 | 「本批」是否含承载该句的那次提交，两种读法都成立，读者无法机械分类 |

**Why:** 这五种共享一个成因——**收尾时我在做的是「概括」，而概括这个动作本身就在丢证据**。写实现代码时，每个断言旁边就是它的实现；写汇总时，断言与证据之间隔了几十轮对话，而「我记得是这样」在那一刻和「我验证过是这样」的**主观确信完全相同**。加之收尾是「任务已完成」的心态，复核强度本就衰减。

单靠自查抓不到，因为自查问的是「我写的是不是我想写的」——五处我都想写那个。**必须有外部 oracle**：要么是命令，要么是评审。

**How to apply:** 收尾产物定稿前，把里面每一个**概括性表述**逐条过一遍，按下面四问，任一答不上就改写或标注为未验证：

1. **这个数字，哪条命令能重新产出它？** 答不上就现在跑一条，按实测改写；跑不出来就删掉，别留一个无来源的数字。（`34/34` 死在这一问）
2. **这句汇总，把什么压掉了？** 尤其「全部通过 / 零问题 / N 路 0/0」这类——**列出被汇总的各项原始计数**，再判断汇总是否还成立。（`四路 0/0` 死在这一问）
3. **这句话描述的动作，方向是哪一边？** 描述自己做过的操作时**尤其**要停一下——`git merge A B` 的两个方向、迁移的源与目标、依赖的上游与下游。用一条能区分方向的命令验证（`git branch --contains`、`git merge-base --is-ancestor`），别靠回忆。（十处方向反了死在这一问）
4. **这是论证还是断言？** 凡出现「必然 / 唯一 / 不可能 / 无穷」这类全称词，把它当作**待证命题**而不是结论：能否举出一个反例？举不出**不等于**不存在。（`无穷回归` 死在这一问）

另外：**判据里出现的每个集合名词（「本批」「这些」「相关的」）都要能枚举**，否则它不可机械判定——见 [[methodology-closeout-doc-goes-stale-the-moment-the-merge-lands]] 的收口。

**与既有条目的分工**：[[feedback-verify-facts-before-superlative-completeness-verdict]] 管的是「**被问**完备性/最优问题时先实测支撑事实」，触发点是他人提问；本条管的是「**主动写**收尾汇总时表述超出证据」，触发点是自己动笔，两者的失效形态与检查动作都不同。[[methodology-closeout-doc-goes-stale-the-moment-the-merge-lands]] 管的是「写时正确、后来变陈旧」；本条管的是「**写的时候就已经不成立**」。相关：[[feedback-pass-null-clean-not-self-validating]]（结论不自证）。
