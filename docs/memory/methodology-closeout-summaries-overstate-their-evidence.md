**收尾阶段写的汇总性表述，系统性地强于它们背后的证据。** 2026-08-08 无损 shutdown 整改的收尾里，我连犯五次，**没有一次是自己发现的**——全部由独立评审抓出。**而这条记忆的第一版，又在自己的表格里犯了其中两条**（把兄弟条目的计数搬来当实例、把「三轮」压成「两轮」），同样由评审抓出：

| 形态 | 实例 | 它错在哪 |
|---|---|---|
| **数字来自记忆，没有 selector** | 「架构与 discovery guards 34/34」 | 从没有一条命令能产出 34。实测是 17 文件 178 pass |
| **汇总压缩掉了真实计数** | 「四路独立评审 0 blocker / 0 major」 | 实施三轮确实 0/0，但**收尾三轮**分别报 0 blocker/3 major、1 blocker/2 major、1 blocker/2 major。汇总把「全部已处置」写成了「从未有过发现」。**本条第一版把「收尾三轮」又写成了「两轮」、漏掉 3 个 major——在演示「汇总压缩计数」时自己又压了一次** |
| **描述自己刚做的动作也会写反** | 「整改已合入 master」 | 方向反了——我把 master 合进了分支，反方向没做。**3 处、3 份文档**（`plan`、`review.md`、`dispositions.md`），出处 `docs/tmp/2026-08-08-lossless-shutdown-closeout-docs-review.md:16`。**本条第一版在这里写「十处」，是把兄弟条目的计数搬了过来**——那个「八处/十处」指的是合并后变陈旧的「待合并」断言，它们**写下时全部正确**，属另一种失效形态、归 [[methodology-closeout-doc-goes-stale-the-moment-the-merge-lands]] |
| **推理被当成证明** | 「自指状态断言存在无穷回归、唯一出口是判定命令」 | 写「已合并」一轮就收敛。真正不可能的是让无锚点断言跨状态持续为真——那是不变量失败，不是修订序列无限 |
| **判据里的集合名词没定义** | 「描述**本批**自身状态时改用判定命令」 | 「本批」是否含承载该句的那次提交，两种读法都成立，读者无法机械分类 |
| **按依赖图报状态时，只写自身缺口、漏掉传播阻断** | History Worker Batch 1b 收尾的 17-stage 表，stage 8／16／17 只标 `❌ 未达成` | 这三项**同时**经 `requires` 链受根阻断点阻断（8 的前置 4／7 受阻于 1；16／17 经 15 继承 1 与 8）。只写直接缺口，读起来像「把这一项补了就清」，而补了也不会达成。**同一条 major 连打两轮**：第一轮我补全了 17 个 stage 却没补依赖语义，第二轮才把两种状态并列写出 |

**Why:** 这几种共享一个成因——**收尾时我在做的是「概括」，而概括这个动作本身就在丢证据**。写实现代码时，每个断言旁边就是它的实现；写汇总时，断言与证据之间隔了几十轮对话，而「我记得是这样」在那一刻和「我验证过是这样」的**主观确信完全相同**。加之收尾是「任务已完成」的心态，复核强度本就衰减。

单靠自查抓不到，因为自查问的是「我写的是不是我想写的」——每一处我都想写那个。**必须有外部 oracle**：要么是命令，要么是评审。

**How to apply:** 收尾产物定稿前，把里面每一个**概括性表述**逐条过一遍，按下面六问，**任一问答不上就执行它的失败动作**，不要放行：

1. **这个数字，哪条命令能重新产出它？** —— 失败动作：现在跑一条并按实测改写；跑不出来就**删掉这个数字**，别留一个无来源的数。（`34/34` 死在这一问）
2. **这句汇总，把什么压掉了？** —— 失败动作：**把被汇总的各项原始计数逐条列出来**，再判断汇总是否还成立。尤其「全部通过/零问题/N 路 0/0」这类。（`四路 0/0` 死在这一问，本条自己又死了第二次）
3. **这句话描述的动作，方向是哪一边？** —— 失败动作：跑一条**能区分方向**的命令（`git branch --contains`、`git merge-base --is-ancestor`），按输出改写。描述自己做过的操作时尤其要停——`git merge A B` 的两个方向、迁移的源与目标、依赖的上下游。（3 处方向反了死在这一问）
4. **这个全称词（必然/唯一/不可能/无穷），我在什么集合上穷举过？** —— 失败动作：**说不出反例的搜索范围，就把它降级为存在性表述**（「在我检查过的 X 里没有反例」）或直接标未验证。**注意不能用「我举不出反例」通过本问**——`无穷回归` 当初正是这样被写下的：举不出反例不等于不存在，而「在什么范围内找过」是可以回答也可以被检查的。
5. **这条判据里的集合名词（「本批」「这些」「相关的」），能枚举吗？** —— 失败动作：**不能枚举就把判据改成可枚举的形式**，或换成运行时判定命令。细节与判定方法见 [[methodology-closeout-doc-goes-stale-the-moment-the-merge-lands]]。（`本批` 死在这一问）
6. **这个「未完成」是它自己的缺口，还是从依赖图传过来的？** —— 只在**有形式化依赖／前置关系**的产物上问（stage 图、任务依赖、门禁链）。失败动作：**两种状态并列写出**，别二选一——`❌ 自身未达成` 与 `⛔ 受阻（来源）` 可以同时成立，且必须写明阻断来源编号。判据是机械的：从每个根阻断点沿依赖图做一次可达性传播，逐项与你写的状态对账。**只写自身缺口会诱导读者以为「补这一项就清」**，那是把一张依赖图读成了一张清单。（Batch 1b 的 stage 8／16／17 死在这一问，且连死两轮）

**与既有条目的分工（按轴切，不按「写时对不对」切）**：

- [[methodology-closeout-doc-goes-stale-the-moment-the-merge-lands]] 管**事实发生变化之后的维护义务**——什么时候要回来改、改哪些携带者、自指状态该换成判定命令。
- **本条管落笔那一刻措辞与证据之间的差距**——数字有没有 selector、汇总压掉了什么、方向对不对、全称词在什么范围上穷举过、集合名词能否枚举、依赖传播有没有漏报。
- **第 6 问有适用边界**：只在产物**带形式化依赖关系**时触发（contract 的 `requires` 图、任务依赖、门禁链）。平铺的清单没有传播可言，别把它当通用要求逐条套。写「X 必须晚于 Y」这类顺序前置本身怎么设计，归 [[methodology-ordering-gate-needs-a-trigger-that-reads-it]]；本条只管**报告状态时**别漏掉传播。
- **两条会在同一次事故里同时触发**，因此有 3 个实例被两边引用（方向写反的那批陈旧断言、`无穷回归`、`本批`）。**细节归 stale 条目，本条只作形态举例**，避免两处各自演化出不同版本。
- 我起初按「写时正确 vs 写时就错」切分，**被评审用 stale 条目自己的正文推翻**——它名下也记着两个「写下时即错」的实例。**教训：切分两条规则时，先去读对方的正文，别按自己脑中的印象划线。**
- [[feedback-verify-facts-before-superlative-completeness-verdict]] 的触发点是**他人提问**（「这是最好的方案吗」），本条的触发点是**自己动笔写汇总**，两者的失效形态与检查动作都不同，不合并。
