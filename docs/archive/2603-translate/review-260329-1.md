## 结论

这次修订把上一次 review 里剩余的建议项也补上了。当前文档已经没有我认为会误导实现或导致行为偏差的阻断性问题，可以直接进入实现。

1. 明确把 `wireRequest.messages` 从 `[]` 改为基于 `wire.input` 填充，解决了 Responses 路径 `wireRequest.messageCount` 恒为 `0` 的系统性问题。

3. 对 history 中 `wireRequest.messageCount` 的语义也说明清楚了：在 Responses 路径里它表示 `input items` 数量，而不是传统的 chat messages 数量。

## 复核结果

上次关注的关键契约现在都已经写清楚：

1. `system/developer → instructions` 使用全量扫描的 `splitInstructionsAndConversation()`，不再误用只提取前缀的 helper。

3. endpoint 路由已经覆盖 legacy / unknown model 的 fallback 语义，不会再把翻译路径的触发条件描述错。
4. `tool.content` 的非字符串情况有显式策略，不再把实现细节留空。
5. refusal / reasoning、`response.incomplete` 的 stream / non-stream 处理都已经统一。
6. `wireRequest.messages` / `messageCount` 的历史记录问题已经被纳入正式设计，而不是留作实现期自行判断。
