## C4 — /responses+ws 腿（responses direct + 前向/反向 @responses + CC→Responses wire + ws）
**Cell**：`(openai-responses, /responses)` direct + `(openai-responses, ws)` + `(openai-cc/gemini/anthropic, /responses)` 前向（via-responses）。
**新 `openaiResponsesLeg`（OUTBOUND_LEGS[RESPONSES] + [WS_RESPONSES]）** —— 锚点：
- `prepareWire`：提取 `prepareOpenAiCcWire` 的 **RESPONSES 部分**（CC→Responses wire：translateChatCompletionsToResponses + normalizeCallIds + prepareResponsesRequest）+ responses direct 的 `prepareResponsesRequest`。
- **R1 corner**：`RETRY_SEMANTICS[openai-responses](RESPONSES)` = **{autoTruncate:FALSE, maxRetries:1}**（direct Responses 无 auto-truncate，`buildOpenAiResponsesStrategiesForEnv`），与 `(openai-responses, MESSAGES)` 的 auto-truncate:true 对比——**补 golden 证 responses direct auto-truncate OFF**。前向 cc/gemini/anthropic @responses = auto-truncate ON（buildOpenAiCcStrategies against CC baseline）。
- exchange 态（responseId/itemId/rebuiltMessages，openai-responses 专属）：per-request exchange scratch（InboundCodec 持，prepareWire 经 env 读）——§11.9 MEDIUM 倾向 per-request scratch 非共享 ctx。
- **HIGH-1**：gemini via-responses 两跳的 `renderResponsesFrameToCc`+`createStreamTranslator` 提取进 hub（gemini InboundCodec 独立持中间 translator 态，delegate 才删得掉）。render(S6) 留 InboundCodec，但两跳原语提取。
- ws：`OUTBOUND_LEGS[WS_RESPONSES]` 复用 RESPONSES leg 的 wire（ws transport 是传输层，wire 相同）。
**验证**：`responses-v4.http`（direct streaming + fallback streaming byte-lock）+ `responses-ws.http` + golden(c) ws/gemini 两跳终帧 + R1 corner golden + 全量 base 5。
