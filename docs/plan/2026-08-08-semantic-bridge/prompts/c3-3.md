# C3.3 —— REST／WebSocket readback 与文档同步

> 开场先读 [README.md](README.md) 的通用红线与必读清单。**本片是 C3 的收口，也是「公共契约在 cutover 前就位」这条硬要求的兑现点。**

## 背景

RFC §10.1 明文：

> C3 在任何 production cutover 前同步 `src/lib/history/types.ts`、`src/lib/context/types.ts`、V3 持久化／投影、History REST／WebSocket 测试、`docs/history.md` 和 `docs/API.md`。**不得把公开契约同步拖到 C11。**

C3.2 落了类型与投影，本片落**对外可读**与**文档**。

## 改动锚点

- Modify History REST route —— `GET /history/api/entries/:id` 返回该投影
- Modify History WebSocket —— 完整 entry 事件沿同一 `HistoryEntry` shape 返回
- Modify 列表／summary 端点
- Modify `docs/history.md`、`docs/API.md`
- Create `tests/history/semantic-bridge-readback.http.test.ts`

**端点 SSOT 是 `docs/API.md`**（见 CLAUDE.md 文档路由）。活的全表面真相 = 运行实例的 `GET /openapi.json`。

## 要落的契约

1. `GET /history/api/entries/:id` 返回完整 `semanticBridgeV2` 投影。
2. History WebSocket 的**完整 entry 事件**沿同一 `HistoryEntry` shape 返回（不是另一套 shape）。
3. `[hard]` **列表／summary 端点不复制大数组**，只可暴露：`semanticBridgeVersion`、actual disposition 计数、是否有 degradation。加断言守护。

## 步骤

1. REST readback 端到端：写入 → `GET /history/api/entries/:id` → **逐字段核对**（不是只核对存在性）。
2. WS 完整 entry 断言 shape 一致。
3. 列表端点断言只出计数、不出大数组。
4. 文档同步：
   - `docs/API.md` —— 补该投影的字段级说明；
   - `docs/history.md` —— 补 lifecycle 与 authority lineage 语义（in-flight vs terminal 的区别、`actual` 空数组与整体缺失的区别、`wirePartialDelivery` 何时投影）。

## ⚠️ 关于服务器

**绝不** `kill`/`pkill`/`killall` 用户在 **4141 端口**的主服务器实例。需要真实 HTTP 验证就起在**其它端口**（如 `bun run start --port 4157`），用独立 history.db 路径，用完按**记录的 PID** 精确清理自己启动的那个。

优先用测试内的 in-process 服务（`tests/e2e-client/harness/serve-in-process.ts` 的现成设施），避免起真实进程。

## 验收

- `bun run typecheck` 绿。
- `bun test tests/history/` 全绿 —— **既有 REST／WS 契约无破坏**。
- `bun run test:backend` 无回归。
- `[hard]` **G2 wire 字节 golden 逐字节对账**（C0.2 锁的那组）：改动前后各跑一次，差异即本片失败，对账结果写进你的进度文件。**本片改 REST／WS 生产代码。**
- 文档确实改了：`rg -n 'semanticBridgeV2' docs/API.md docs/history.md` 非空。
- **通读一遍你改的文档**。编辑成功 ≠ 文档正确：核对标题与内容相符、差异表声称改了的地方正文真的改了、没有整段重复。
