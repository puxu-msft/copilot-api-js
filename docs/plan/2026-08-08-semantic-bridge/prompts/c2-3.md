# C2.3 —— delivery authority 与原子 transfer

> 开场先读 [README.md](README.md) 的通用红线与必读清单。
>
> **这是整个 RFC 最容易做错的一片。** 它的不变量是「任一时刻至多一个 candidate 能写客户端」，而这类不变量的特点是：**读代码判不出来**，全绿的测试也证不了。必须有能确定性停在发布中点的探针。

## 背景

RFC §6 要求「request 在任一时刻至多一个 candidate 持 active delivery authority」。现有代码里没有 authority 概念，本片加上它。

## ⚠️ 先纠正三次写错的前提 —— 这是本 kickoff 最重要的一节

本 kickoff 被评审推翻过**三次**，三次都是同一族错误：**把一个只在某作用域内成立的事实写成全称断言**。你**不要继承任何一版**：

1. 「`writeCommittedBatch` 是唯一客户端 writer」—— 漏掉同文件的 `write()` 主路径。
2. 「`writeToSink` 是所有客户端字节的漏斗」—— 在流式内**完全正确**，漏掉非流式 `c.json`。**而且为它加的守卫会为这个假全称背书。**
3. 「客户端字节有两条互不相交的路径」—— 漏掉 handler／lib **自持 `streamSSE`** 的第三类。

**共同根因**：修一个过宽断言时**只把名字换窄**，没有主动去构造跨作用域的反例。每次都以为「这次总该穷尽了」，而判据的形状（守卫冻结的是上一次那条路径的**内部**）恰好让新缺口隐身。

**所以本片按枚举组织，不按二分。** 先问「**谁能向客户端写字节**」，再谈分类。

`[hard]` **第 ③ 类里的 `error-shaping-glue` 直接证伪了本片的不变量 5**：那条不变量要求「错误 wire 仍由该 active authority 发送……不允许无 authority 的 writer 代发」，而这条既有路径正是一个**无 authority 的 writer 在发错误帧**。**你必须先处理这个既有矛盾**——给它落 authority，或显式裁决豁免并写明理由与 History 后果。**不得假装不变量已经成立。**

另一个已实测的陷阱：`reservation.commit()` 只改 allocator 内部计数器，**不改变 owner 归属语义**。`GenerationWireState`（`src/lib/pipeline/types.ts:509`）需要**新增** authority 字段 —— 别复用 `activeLeg`，那是 leg 不是 authority。

## 要落的不变量（逐条一测）

**唯一性 —— 且必须双向证明**

1. `[hard]` request 在任一时刻**至多一个** candidate 持 `active` delivery authority。
   ⚠️ 「至多一个」在 active 数为 **0** 时同样成立，所以这条断言**单独没有判别力**。必须配**存在性正控，且三类各一条**：
   - **①**：普通流式请求首帧写出后存在**恰一个** `active`；恢复批次发布后同样。
   - **②**：`c.json` 返回前存在**恰一个** `active`，返回后转 `terminal`。**且至少覆盖 messages 与 responses 两个路由** —— 只测一个路由，另一方向的洞照样全绿。
   - **③**：错误整形腿写出前存在**恰一个** `active`（或已显式裁决豁免，且该裁决本身被断言）。
2. 未持 authority 的 candidate **不得写任何客户端 sink**。
   ⚠️ **这是个全称，它的证据必须由三部分合起来给**，不能只指向 `writeToSink` 守卫（那条只覆盖 ①，把无限定全称指向单类守卫，正是本 kickoff 前三版的失效原型）：① 的 `delivery-writer-set` 守卫 + ② 各路由的存在性正控 + ③ 自持 `streamSSE` 的落点与正控；外加 `client-byte-origins` 守卫兜住第四类。
3. `active` candidate 只有在其 terminal wire **发送完成或明确记录 wire delivery failure 后**，才能原子转为 `terminal`。

**初始 commit**

4. 通常首次不可逆客户端 emission 是初始 authority commit point，建立 `active(epoch=0)`。
5. **preflight fail-closed** 也必须建立唯一 authority：driver 在接受该 candidate 的 typed rejection 时建 `active(epoch=0)`、晋级其 semantic observations、冻结 `failed/preflight-reject` response terminal；**错误 wire 仍由该 active authority 发送并等待 sink 结果**，随后才原子转 `terminal`。发送／ACK 失败时同一 authority 记录 wire delivery failure 后再转 terminal，**不允许无 authority 的 writer 代发**。
6. **合法 contentless success** 同样先建立 active authority，发送并确认 terminal wire 后才转 terminal。
7. commit 前的可重试失败仍从 immutable baseline fork，旧 candidate 标 `discarded`，其 proposed observations **只作 candidate 诊断，不进请求级 actual**。

**post-commit transfer**

8. commit 后的恢复**不是第二个 winner**，是同一 committed lineage 内的 authority transfer。
9. 顺序 `[hard]`：祖先先把开放 part／item 按**真实** provenance 终结为 partial → 按目标协议顺序发送并**确认**所有必需的 closing wire effects → 准备好后代首个可发送 effect → **只有祖先 wire lifecycle 已闭合后**，driver 才在**同一临界动作**内把祖先 `active(N)` 改为 `transferred(N,toCandidateId)`、后代 `uncommitted` 改为 `active(N+1)`。
10. 准备、closing sink ACK 或临界校验**任一失败**都不发布 transfer，authority 仍归祖先。发布成功后 authority 只归后代。**任何瞬间都不可双 writer。**
11. 后代首个 effect **只能在 transfer 成功后**发送。

**pre-commit fallback retain：两支，且不允许第三种行为**

12. **分支①（旧 segment 有可发客户端 wire effect）**：旧 candidate 先建立 `active(epoch=0)` → 按客户端协议 flush 并 ACK retained partial 与 closing lifecycle → 再原子 transfer 给 fallback candidate `epoch=1`。**纯 semantic observation 不算可发内容。** flush／ACK 失败则不 transfer，旧 authority 记录真实 delivery failure 后 terminal。
13. **分支②（旧 segment 没有任何可发客户端 wire effect）**：保留为空是空操作 —— 旧 candidate discard，fallback candidate 到首次写出时**直接建立 `epoch=0`**，**不产生 transferred ancestor，也不产生 `wirePartialDelivery`**。具名 normalized observation **归属 fallback candidate／新 segment**，先为 proposed，在该 candidate 建立 epoch 0 时随其余 observation 晋级 actual；**不得留在已 discarded 的旧 candidate 上**。

**其它**

14. post-commit fallback 只允许 `partialOutputKept:true` 并走 transfer；**该 phase 不存在 false 类型分支**，解码到等价非法组合须 fail-closed。continuation 只存在 post-commit true 分支。
15. hedge losers 无论是否完整解析都标 `discarded`，**不得**写客户端、请求级 WARN、History actual observations 或业务指标。初始 authority 选择与所有 pre-commit loser discard 在**同一 driver 临界动作**内发布。
16. `authorityPhase` 由 driver **据锁内事实**派生，**不接受客户端／上游 wire 自报**。boundary 处理必须在与 authority commit／transfer **相同的临界区内**复核 phase；陈旧或矛盾值不得按原分类执行，driver 须据锁内事实重新构造合法 update，**无法重构则 fail-closed**。

17. **导出接线坐标供 C3.1 消费** `[hard]`：把「当前 candidate 的 authority 状态」暴露为一个**具名导出**（如 `readDeliveryAuthority(...)`）。C3.1 的 observation 晋级**必须 import 它** —— 这样两片接在同一处由**编译错**保证，而不是靠你在进度文件里写一段散文交代、而下一个人可能没读到。

## 测试手法：确定性中点探针

`[hard]` **光读代码判不出原子性。** 你需要一个能**确定性停在发布中点**的探针：在 transfer 的临界动作中途暂停 → 读取派生状态 → 断言中间态一致（恰一个 active）。

现成设施：`src/lib/pipeline/delivery/session.ts:59` 的 `DeliverySessionTestHooks`（`onWrite` / `onBeginLeg` / `onCommittedAllocation` / `onBeforeRecoveryBatchCommit` / `onCloseAnchor`）—— 这些 hook **就是为这类中点探针设计的**，跑在真实 delivery session 内部。优先用它们，不要另建 fake session（自造 sink 看不到真实 handler↔driver 缝）。

其中 **`onBeforeRecoveryBatchCommit` 专门对应 `:492` 那条空 commit 回调的路径** —— 它是 mutation 6 的探针。

可复用的 harness：`tests/e2e-client/anthropic-sdk.it.test.ts`、`continuation-sdk.it.test.ts`、`precontent-recovery.it.test.ts` 已覆盖 pre/post-commit retry 与 continuation 的真 SDK 场景。

## Mutation（必做，九条，逐条核对失败来自目标机制）

1. 让 transfer 在 closing ACK **之前**发布 → 中点探针的「恰一个 active」断言变红。
2. 让 preflight reject **不建立** authority → 该终态的 lineage 用例变红。
3. 让 pre-commit **空 segment** 也产生 transferred ancestor → 分支②用例变红。
4. 让 flush 失败**仍然** transfer → 分支①失败支用例变红。
5. **让 ① 的主路径 `write()`（`:165`）不带 epoch** → ① 存在性正控变红。
6. **让 `publish-recovery-batch`（`:492`）那条路径不带 epoch** → 以 `onBeforeRecoveryBatchCommit` 为探针的正控变红。
7. `[hard]` **让某个非 messages 路由（如 `responses:269`）的非流式不建 authority** → 该路由的 ② 正控变红。
   **必须打非 messages 路由**：只打 messages 只证明了一个路由，而反方向的洞正是靠这条抓。
8. `[hard]` **让 ③ 的 `error-shaping-glue` 不建 authority** → ③ 正控变红。
9. **临时新增第四类客户端写出**（加一处 `c.json` 或 `streamSSE`）→ `client-byte-origins` 守卫变红。
   **这条验证的是「下一次同类错能不能被抓住」本身** —— 本 kickoff 已在同一处错了三次，这是唯一能阻止第四次的机械判据。

每条撤销都用 exact reverse patch。**某条不红说明你的测试在测别的东西**，回去查，别改断言。
