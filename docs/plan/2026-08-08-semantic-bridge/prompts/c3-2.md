# C3.2 —— History V3 类型与双路径投影

> 开场先读 [README.md](README.md) 的通用红线与必读清单。

## 背景

RFC §10.1 定义了本 RFC 的**单一权威 History 投影** `HistoryEntry.pipelineInfo.translation.semanticBridgeV2`，两个方向共用 versioned envelope。

`[hard]` **RFC 明确要求这份公共契约在任何 production cutover 之前就位，不允许拖到 C11。** 理由：degradation 与 History 是功能切换的**前置基础设施**，不能先上线 WARN、后补持久化。

## ⚠️ 本片最容易漏的一点：History 有两条投影路径

这一条是主会话实测确认的，**别只改 V3 projection 就以为接完了**：

| 路径 | 锚点（开工先复核行号） | 现状 |
|---|---|---|
| **terminal** | `src/lib/history/v3/projection.ts:187` `recordToHistoryEntry`、`:388` `pipelineInfo` 取自 `terminalMeta` | `pipelineInfo` **只经 terminal metadata 落地** |
| **in-flight** | `src/lib/history/in-flight.ts:54` `putInFlight`、`:58` `updateInFlight`；`src/lib/history/entries.ts:33` 发布 `history.entry_updated` | in-flight 是**独立的内存 `HistoryEntry` 映射**，根本不走 V3 record |

RFC §10.1 的 `lifecycle: "in-flight"` variant 要求活状态实时可见 → **两条路径都必须接**。

## 单一真相源的做法

`[hard]` **不要让两条路径各存一份**——那必然漂移。

建议：活状态挂 `ModelOperationRecorder.setExtension("translation.semanticBridgeV2", …)`（`src/lib/context/model-operation-record.ts`），in-flight 与 terminal 两条投影**都从该 extension 派生**。

注意 `setExtension` 在 terminal committed 之后调用会抛（见 `tests/context/model-operation-record.unit.test.ts:332` 的现有断言），这正是你要的 fail-fast。

## 要落的契约

类型逐字对齐 RFC §10.1，不得增删字段。重点：

1. **`lifecycle` 判别联合**：`in-flight` 的 `authorityLineage` 可为空 tuple 或 `[...Transferred, Active]`；`terminal` 的**必须**是 `[...Transferred, Terminal]`（非空 tuple 在类型层保证 terminal leaf 存在）。
2. **epoch 从 0 严格递增**；每个 transferred entry 的下一项必须以其 candidate 为 predecessor，且 `toCandidateId` 等于下一项的 candidate；`cause` 与其 `segmentTerminal.provenance` 同为 fallback 或 continuation。
3. **整体 response terminal 的唯一 owner 是 terminal leaf 的 `terminal` 字段**，不另存顶层副本。
4. `actual` 只含 authority lineage 的 committed／emitted observation；discarded／shadow 只能位于 `candidateDiagnostics` 的 `candidates[].proposed`。
5. **`actual` 为空数组** = 已捕获且确无 actual observation；**整个 `semanticBridgeV2` 缺失** = 旧记录／未捕获。`[hard]` 两者不得混淆，缺失**不得外推为「没有退化」**。
6. `candidateDiagnostics` **不可省略**：`captured` 要求 `total === candidates.length`；`pruned` 要求 `total > retained` 且 `retained === candidates.length`；`not-captured` 表示 producer 未收集明细。
7. `wirePartialDelivery` **只在** lineage 含 transferred ancestor、或 terminal leaf 为 `terminalWire:"failed", committed:true` 时投影。完整成功的 `acknowledged + committed:true` **不构成** partial delivery。
8. **opaque hash** 固定为 `SHA-256("semantic-bridge-opaque-v2\0" || kind || "\0" || rawOpaqueUtf8Bytes)` 的 lowercase hex。hash 用于同请求内关联与诊断，**不承诺跨版本内容寻址**。
9. `[hard]` **History 不存 raw opaque 正文**。加一条守护测试。
10. `lifecycle`、`config`、`authorityLineage`、`actual`、`candidateDiagnostics` 在 v2 记录中**均不可省略**。
11. 旧记录没有 `semanticBridgeV2` 时按 unknown capability 处理，**不回填虚构默认**。

- `bun run typecheck` 绿。
- `bun test tests/history/` 全绿；`bun run test:backend` 无回归。

## Mutation（必做，两条）

1. 让 History 写入 opaque 正文 → 第 9 条守护变红。
2. **只更新 terminal 投影、不更新 in-flight** → in-flight 可见性用例变红。**这条专防「只改 V3 projection 就以为接完了」**，是本片最重要的一条 mutation。
