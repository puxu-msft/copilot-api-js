# C1.2 —— 三层 terminal 与拒绝规则

> 开场先读 [README.md](README.md) 的通用红线与必读清单。**仍无生产调用者。**

## 背景

这是整个 RFC 里不变量最密集的一片。原因是现有代码在这里错得最系统：A-3 的 `flush` **无条件发 `response.completed`**，只把 status 字段填成 incomplete —— 也就是说，一个被截断的响应在 wire 上宣称自己完成了。RFC §4 因此把 terminal 拆成 part／item／response 三层，并规定了一整套「什么情况下**不许**终结」的拒绝规则。

**这些规则必须逐条落、逐条测。** 漏掉一条不会有任何征兆——测试照绿，直到某天一个被截断的流骗过了客户端。

## 必读

RFC §4「Ledger invariants」中 terminal 相关的全部条目。下面「要落的规则」是它的执行清单，**清单不得省略**；若你发现清单与 RFC 有出入，以 RFC 为准并回报。

## 要落的规则（逐条一测）

**通用**

1. terminal 后拒绝一切更新。
2. `complete`／`partial`／`discarded` 是 item 和 part 共同的 terminal 语义。

**层级关系** —— 这条最容易做错

3. `finish-item` **不得隐式终结 child part**。任何 item terminal 前，所有已 declare 的 part 都必须已 terminal。不满足则 reducer **拒绝该 transition**，**不由 emitter 补完或跳过 child**。

**按 item 终态分支**

4. item 标 `complete`：非 discarded part 必须**全部** complete；discarded part 必须已有具名 degradation；**不得含 partial part**。
5. item 标 `partial` 前：所有开放 part 必须先以具名 EOF／abort／fallback／continuation／wire-error provenance 终结为 `partial`；既有 complete／discarded part **保持原终态**。
6. item 标 `discarded` 前：所有开放 part 必须先以同一或派生 reason 终结为 `discarded`。

**kind-specific 权威值门**（complete item 额外满足）

7. reasoning／text：所有目标投影 part 已 terminal 且可派生 final visible。
8. function／server-tool call：已有 `CallMetadata` 与 `authoritativeArguments`。
9. function／server-tool result：已有 `ResultMetadata` 与 `authoritativeOutput`。
10. `drop` 永远只能 `discarded`。
11. **缺任一权威值时不得用 delta 拼接值冒充 done** —— 这正是 A-3「无 arguments delta 的 function call 变空 input」的对偶错误，别在新代码里换个方向重现。

**provenance 配对**

12. partial provenance 为 `fallback` **必带** `fallbackId`；为 `continuation` **必带** `continuationId`；其它 provenance（`eof`／`abort`／`wire-error`）**不得带**二者。
13. `discarded` **必带** reason。

**response 层**

14. 每个 response **恰有一个** response-level terminal。
15. `completed` 前：不得存在开放 item／part，且所有非 discard item 必须 complete。
16. `incomplete`／`failed`／`cancelled` 前：必须先按**实际** provenance 逐个把开放 part 与 item 终结为 partial 或 discarded。
17. `incomplete`／`failed`／`cancelled` **不得被改写为 `completed`** `[hard]`。这是 A-3 缺陷的直接对治。
18. 缺 wire terminal 时，只能由 EOF／abort／driver-cancel provenance **合成对应的非成功终态**，不得合成 `completed`。
