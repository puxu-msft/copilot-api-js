5. **多个 reasoning item 被单槽压扁** —— A-5 `:163-173`、A-6 `:129-139` 只有一个 `reasoningEncrypted`。
6. **non-stream encrypted-only reasoning 被丢** —— A-5 `:210-219` 只有 text 非空才生成 thinking。
7. **无 arguments delta 的 function call 变成空 input** —— A-3 `:258-271` 不读 start block 的完整 input，flush 靠 `argumentParts.join("")`。
8. **incomplete payload 仍发 completed event** —— A-3 `:482-501` 无条件发 `response.completed`，只把 status 填成 incomplete。

## Mutation（必做）

把 `src/lib/openai/translate/responses-to-anthropic.ts` 的 `reasoningEncrypted` 从单值改成数组保留多条，重跑 —— **encrypted-only 与 multi-reasoning 两条 KNOWN-LOSS 断言必须变红**。这证明它们确实咬住了当前的有损行为，而不是恒真的空断言。

⚠️ **变异的注入与撤销方式是强制的**，因为这是一个你没有提交的生产文件：

1. **先构造一份只描述该变异的 exact patch**，用 `git apply` 注入它。顺序是「先有 patch、再有变异」。
2. 撤销时对**同一份冻结的 patch** 执行 `git apply --reverse`。先跑 `git apply --reverse --check`，失败或与当前改动重叠就**停下问用户**，不要强推。
3. **绝不用整文件 `git checkout` / `restore` 撤销** —— 共享树里那个文件可能同时含主会话或同伴的未提交 WIP，整文件回退会连它们一起抹掉。

反面做法（别做）：在注入变异前跑 `git diff <file> > /tmp/x.patch` 当基线。那一刻变异还没注入，这份 diff 捕获的是**真实实现或同伴的 WIP**，反向应用它等于把这些改动删掉。

做完 `git diff` 复核：出现不属于该 patch 的改动就停手。
