# C3.1 —— typed observation 与 stage 晋级

> 开场先读 [README.md](README.md) 的通用红线与必读清单。**observation 只记录，不改变任何 wire 行为。**

## 背景

RFC §10 的核心区分：**「mapper 计划保留」不等于「客户端收到」**。现有代码里降级信息只有一个扁平的 `AnthropicToResponsesTranslationDegradation`，分不清「我打算这么处置」「这个处置已被 authority 接受」「客户端确实收到了对应字节」三件事。于是 hedge loser 的诊断和真实交付混在一起，History 里看不出区别。

三态：`proposed` → `authority-committed` → `sink-emitted`。

## 必读

RFC §10 全节（含 `TranslationObservation` 类型与其后的七条约束）。

## 改动锚点

- Create `src/lib/pipeline/semantic/observation.ts`
- Modify `src/lib/context/request.ts` —— **仅**请求级 WARN 聚合与 terminal 记录接点。相关锚点 `:1494` `selectGenerationWinner`、`:901` `commitGenerationObservabilityTerminal`（**开工先复核行号**）
- Create `tests/pipeline/semantic/observation-stage.unit.test.ts`

**接线位置由编译期保证，不靠进度文件**：`[hard]` 晋级判定**必须 import C2.3 导出的 authority 读取接口**（如 `readDeliveryAuthority`），不得自行从 `request.ts` 另找一处 authority 近似物。

⚠️ 注意 `request.ts` 的锚点是**聚合与记录**用的，**不是** authority 真相源 —— authority 住在 `delivery/session.ts` 那一层。这两处不是同一个地方，别把 stage 判定接到 `request.ts` 上。若 C2.3 的具名导出不存在，说明它未完成不变量 17，**停下回报，不要绕开自己造一个近似判定**。

## 要落的不变量

1. `observationId` 在整个 request 内唯一；**每个 ID 任一时刻只有一个当前 stage**。
2. 晋级是**原记录的原子状态替换**，`[hard]` **不是在 `actual` 追加第二份副本**。
3. stage **不得回退**，也不得跳过必要的 sink ACK。
4. Semantic mapper 只产 `proposed` 语义事实，**不自行声称 delivery authority 或 sink 效果**。
5. driver 接受 update 时读 candidate 当前 authority：从未获权／已 discarded 的 candidate 保持 `proposed`；当前 `active(epoch=N)` 的 candidate 产生的 observation **在同一动作中**写为 `authority-committed` 并携 `authorityEpoch:N`。（这样初始 commit **之后**才出现的流式 observation 不会遗漏。）
6. 初始 authority commit point 把该 candidate 此前**所有** proposed observation **原子晋级**为 `authority-committed(epoch=0)`。
7. 后续 authority transfer 只让**新** candidate 的**新** observation 用新 epoch，**不重复晋级祖先记录**。
8. shadow 永远没有 authority，**全部停在 proposed**。
9. `effect:"semantic"`（strip 未知 opaque、丢弃无等价 capability、normalize order 等）：一经 authority 接受即成为 actual，**不要求存在对应 wire byte**，`authority-committed` 就是终态。
10. `effect:"wire"`（声称客户端收到某投影）：必须由 sink **ACK 同一 observationId** 后才从 committed 晋级 `sink-emitted`；wire 失败则**保留 committed 但不产生 emitted**。
11. `preserved`／`normalized` 同样遵守 effect 与 stage —— 它们不是「天然成立」的。
12. 请求级 WARN 与 History `actual` **只从 authority lineage 的 committed／emitted 聚合**；candidate diagnostic 可保留其他 proposed 事实，**不得混入 actual**。
13. `transferred` 祖先在其 epoch 内已 committed 的事实**仍是 actual**，不因 leaf 变化被抹掉。
14. 同 reason／quadrant／stage 的 actual observation 请求级聚合，日志**至多一条**。
15. 默认 fail-closed 使用**稳定 error code**；`[hard]` retry／客户端逻辑**不得解析英文 message**。
16. **delta/done 冲突 observation 的 producer 在此落地** —— RFC §4 要求 part **text**、**arguments**、**result output** **三者**的冲突都产生 observation。C1.3 只为三类留了结构位，本片补齐**实际生成**。
    ⚠️ **不要只做 arguments 那一类**：另两类没有任何其它片承接，漏了就永久落空，而且不会有任何测试变红。

## 步骤

1. 落 `TranslationObservation` 类型（RFC §10 逐字）。
2. 实现 stage 状态机与晋级动作。
3. import C2.3 的 authority 读取接口，在其上做 stage 判定。
4. 补齐三类 delta/done 冲突的 observation 生成。
5. 逐条补测。

## Mutation（必做，四条）

1. 让晋级变成**追加副本**而非替换 → 「每 ID 单一当前 stage」用例变红。
2. 让 `effect:"wire"` 的 observation 在 sink 失败时也晋级 `sink-emitted` → 第 10 条用例变红。
3. **让 part text 的 delta/done 冲突不产生 observation** → 第 16 条对应用例变红。
4. **让 result output 的 delta/done 冲突不产生 observation** → 同上。
