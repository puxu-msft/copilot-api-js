## 为什么这样实现

九类 KNOWN-LOSS 直接调用六个现有 translator，断言当前有损结果；修复这些缺陷时，旧结果断言会变红，迫使 C8–C10 显式更新。G4 守护走同模型 Anthropic request rewrite，并构造完整的 thinking／redacted_thinking／text／tool_use 加配对 tool_result 回合，避免 orphan-tool 清理把不合法 fixture 的失败误判为 G4 回归。

G2 wire golden 使用官方 SDK 的 custom `fetch` 访问 `serveInProcess()`，在 localhost HTTP `Response` 到达 SDK、但尚未被 SDK 解析前 clone 并读取完整实体字节。九条 golden 覆盖两方向 × stream／non-stream × retry／no-retry，并额外覆盖 R→A stream reasoning summary + encrypted content。Bun snapshot 可被 `bun test -u` 静默重写，因此测试文件内另有固定 byteLength／SHA-256 权威表；digest 只能随对应 C9／C10 cutover 在同一个经评审的 commit 更新。

## 试过但不成立的路

最初用 wire mutation 改 `response.reasoning_summary_text.delta`，八条基础 golden 仍绿。按“mutation 不红有三解：测试没咬住／mutation 没生效／fixture 造不出状态”排查：patch 已实际生效，测试捕获点也在真实客户端边界，最终确认 fixture 完全没有 reasoning，属于第三解。没有调整 golden 迁就 mutation，而是先用基础 fixture 必经的 text event 完成 wire 判别力正控，再新增专门携带 summary 与 encrypted content 的 reasoning golden，并对 reasoning event 单独重跑正控。

reasoning golden 的 mutation 将 `response.reasoning_summary_text.delta` 改一个字节为 `response.reasoning_summary_text.deltb`；目标用例变红，SDK 可见 summary 由 `reasoning summary golden` 变为空，证明该内容域已被 wire gate 覆盖。
