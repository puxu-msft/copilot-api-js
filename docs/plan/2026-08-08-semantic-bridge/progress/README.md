# 进度文件约定

一 agent 一文件，文件名 = 你的片 ID（如 `c1-2.md`）。**随每个实现 commit 一起提交**，不要攒到最后。

## 只记 git 记不下的三样

git 已经记录了「改了什么」和「什么时候改的」，进度文件不重复这些。它只记：

1. **为什么这么选** —— 有多个可行做法时，你选了哪个、依据是什么。特别是 RFC 没写死、你自己拍板的部分。
2. **试过什么没成** —— 走过的死路。这是对接手者最有价值的信息，能省下重走一遍的时间。
3. **下一步卡在哪** —— 当前的阻塞点、待确认的疑问、你留下的 TODO 及其判据。

## 模板

```markdown
# <片 ID> —— <片名>

**状态**：进行中 | 已完成 | 阻塞
**分支 / worktree**：
**已提交**：<commit sha 列表，随进展追加>

## 决策

- <决策>：选了 X 而非 Y，因为 <依据>。RFC <节> 没写死这一点。

## 试过没成

- <做法>：<为什么不行，附证据>

## 卡点与待办

- [ ] <待办>，验收判据：<怎么算做完>，证伪方式：<怎么证明它没做到>

## 给接手者

<如果你被中断，接手者需要知道的最少信息>
```

## 纪律

- **写完即提交**，不要攒。中断即全丢是真实发生过的。
- **状态断言带证据** —— 「测试全绿」写成 `bun run test:backend` 于 `<sha>` 全绿；数字带口径。
- **别写成完成叙事** —— 它是工作台账，不是汇报材料。没做成的部分照实写。
