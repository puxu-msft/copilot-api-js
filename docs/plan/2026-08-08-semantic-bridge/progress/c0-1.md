# C0.1 进度

## 为什么这么选

- Anthropic 侧共享完整的 SDK 解码与累积、`event:` 不变量和 wire 序列化，因为这些逻辑只解释 Anthropic wire，不依赖任一 translator。
- Responses 侧共享真实 OpenAI SDK、in-process proxy 和 scripted upstream 的组合，并由调用方传 model；保留既有测试对模型状态、fixture 与 passthrough wire 的所有权，避免把场景特有行为塞进 oracle。
- 为 Anthropic 不变量保留独立自验用例：破坏输入帧而非移除检查，才能长期证明 oracle 有判别力。

## 试过什么没成

- 原 mutation 规格要求移除 `event:` 检查后既有测试变红；实测仍为 30 个用例、0 失败，assertions 从 151 降至 106。移除检查测的是检查是否存在，不是检查是否有判别力；被测对象是 oracle 自身时，必须破坏被检查对象。更正后的缺失 `event:` 输入会按目标机制抛错。
- 首轮委派目标目录与实际 cwd 不一致：子 agent 实际 cwd 绑定发起会话的树，`isolation` 参数与提示词都不改变它。后续片动手前必须同时打印 `pwd -P` 与 `git rev-parse HEAD`，不能从提示词推断工作树。
- 基线只记用例数不够：用例数不变只能证明没有删整条用例，assertions 数不变才能发现用例内部丢断言。本片冻结并复验 Anthropic 30/151、Responses 15/21。
- 判别力自验必须逐条覆盖被测函数中的每一条谓词，不能以“整体抛错”代替；短路会让后置谓词永远不可达。本片分别用缺失 `event:` 与“event 等于 JSON type、但 SDK 不识别”两种输入命中两条 N1 谓词。
