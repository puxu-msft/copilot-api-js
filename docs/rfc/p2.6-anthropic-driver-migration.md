# RFC — P2.6: Anthropic /v1/messages 切统一 v4 driver

**状态**：**已收敛**（3 轮对抗 review 完成，待用户确认后实现）
**作者**：Claude（P2.6 规划会话，2026-06-17）
**前置**：P2.1-P2.5 ✅（driver + openai-cc/openai-responses/gemini codec 全在 driver；flag 全 ON）
**为何 RFC**：Anthropic handler 单文件 1063 行，是 P2 最复杂、最高风险迁移（最常用路径 = Claude Code 的 /v1/messages），触发项目「≥1000 行重构先 RFC + 3+ 轮对抗 review + commit invariants」纪律。
**review 收敛**：3 轮对抗 subagent review + 主线亲自核验，**揪出 2 个影响所有格式的 CRITICAL 共享 driver 契约 bug**（§11.1 driver 返回 pre-retry env；§11.2 onResolved 无 meta 通道）——均在写任何 byte-critical 代码前发现。round-3 判定收敛（C0-① 逐字段核验不回归；C0-② 机制已更正为 widen env-`RetryAction.meta`）。**实现顺序见 §11.6（C0 共享契约前置 → C1-C5）。**

## 1. 目标与范围

把 Anthropic **直连路径**（streaming + non-streaming）切到统一七阶段 driver，新旧并存（flag `anthropic` 可回切），逐字节等价（L1 行为 ∧ L2 记录）。Anthropic 是「旁路直连」——translateOut/renderResponse identity，但**改写最重**（sanitize 链 + B1-B12 prepare）、**重试最多**（8 策略）、**pump 最 byte-critical**（recoverer + decoder + server-tool-filter + thinking-sig-shim + heartbeat 交织）。

### 范围内（P2.6）
- `handleMessages` 的直连路径：`handleDirectAnthropicCompletion` → driver。
- streaming pump（`processOneStreamEvent` 等）+ non-streaming response 处理：**复用现有函数**，handler-v4 只换请求侧（driver 替 runAnthropicPipeline）+ 流源（driver.runResponse 替 processAnthropicStream）。

### 范围外（明确暂缓，文档化为遗留）
- **web_search 双跳**（`handleWebSearchCompletion`，286 行，独立编排：两次非流式 hop + 真实搜索 + 合成响应）。默认关闭（`state.webSearchEnabled`）。route-v4 保留 `if (webSearchEnabled && payloadHasWebSearch) → handleWebSearchCompletion(legacy)`，**不进 driver**。理由：双跳是「单请求 → 多上游调用」编排，不契合 driver 的「单请求单 exchange」模型；其内部已用 `runAnthropicPipeline`（legacy），与直连迁移正交。**P2.6-D-websearch 遗留**：未来用 driver.workflow 或 codec 子流程重做。
- **count_tokens**（`handleCountTokens`，本地 tokenizer，无管线）：route 保持 legacy。
- **warmup**（`isWarmupRequest` 早拦截）：route 保持 legacy（在 driver 之前）。

## 2. Codec 设计（`src/lib/codec/anthropic.ts`）

per-request 工厂 `createAnthropicCodec()`，实现 `FormatCodec` + 扩展访问器。

### 2.1 parse（S1，同步）
复现 `handleMessages` + `handleDirectAnthropicCompletion` 的请求侧 setup（**system-prompt 已由 route 前置 async 注入**，对齐 CC/Responses/Gemini 的 P2.2-D3）：
- `incoming = raw.body`（post-system-prompt）；`clientBody = raw.originalBodyForHistory ?? raw.body`（client 原始）。
- `originalSnapshot = structuredClone(clientBody)`。
- model 解析（`raw.preResolved` / `resolveModelName`）。
- 建 ctx（endpoint `anthropic-messages`）+ `setOriginalRequest`（Anthropic-shape：messages/tools/system + payload=snapshot，model=client 原名）+ `setInboundRequestHeaders`。
- tool-name mapper（`buildAnthropicToolNameMapper(incoming.tools, model, vendor)`）+ `setToolNameMapper`。
- `setResolvedModel`。
- **preprocess + 初始 sanitize**：`preprocessAnthropicMessages(incoming.messages)` → `runAnthropicRequestRewrites(payload, {toolNameMapper})` → `{payload: initialSanitized, sanitizeResult}`。
- `env.body = initialSanitized`（Anthropic-shape，sanitize 后；**B1-B12 prepare 在 prepareWire**）。
- **truncate baseline** = `anthropicPayload`（preprocess 后、initial-sanitize 前——对齐 legacy `originalPayload`，auto-truncate 从此 re-truncate）。
- **暴露给 handler**（扩展接口）：`getContext()`、`getTruncateBaseline()`、`getInitialSanitizationInfo()`（sanitizeResult.stats）、`getPreprocessInfo()`、`getResanitize()`（directSanitize 闭包，供 handler 的 onRetry message-mapping）。

> **OQ-parse-1**：thinking feature 记录（`recordFeature("thinking", {type})`，handler.ts:348）放 codec.parse 还是 handler？legacy 在 runInitialSanitizationAndRecord。建议 codec.parse 后 handler 读 `env.body.thinking` 记录（与 CC 的 recordFeature 在 handler 一致）。

### 2.2 decideRoute（S2）
`supportsDirectAnthropicApi(env.model.id)` → supported ? passthrough `/v1/messages` : reject 400（`Model "X" does not support /v1/messages: ${reason}`）。**无降级**（对齐 messages:167，旁路直连无 fallback）。

### 2.3 translateOut / renderResponse / renderResponseNonStreaming（S2/S6）
**全 identity**（直连，无协议翻译）。renderResponse(frame)=frame；renderResponseNonStreaming(upstream)=upstream。

### 2.4 prepareWire（S4）
`prepareAnthropicRequest(env.body, {resolvedModel, clientAnthropicBeta, excludeBetas: env.prepareHints.excludeBetas, rejectFields: env.prepareHints.rejectFields})` → `{wire, headers}`。
- `clientAnthropicBeta` 从 inbound header（codec 闭包持有，parse 时从 raw.headers 取）。
- **betaProbe.recordOutbound(headers)**：codec 持 betaProbe，prepareWire 后记录出站 betas（替 legacy adapter 的 onPrepared）。
- **wire-thinking feature**（`recordFeature("thinking-wire", {type})`，pipeline.ts:146）：prepareWire 后从 `wire.thinking` 记录。
- 返回 `PreparedRequest{url:/v1/messages, headers: new Headers(headers), body: wire, stream: env.body.stream ?? false}`。

> **OQ-prepare-1**：betaProbe 是「codec 记录 + strategy 读」的跨组件状态。方案：handler 建 betaProbe，注入 codec（prepareWire 记录）+ strategies 工厂（unsupported-beta strategy 读 `getProbeCandidates`）。codec 暴露 `setBetaProbe(probe)` 或工厂参数 `createAnthropicCodec({betaProbe})`。

### 2.5 sampleRequest（S4 双轨）
- effective：`env.body`（Anthropic-shape，sanitize 后逻辑请求），format `anthropic-messages`，messages=`env.body.messages`。
- wire：prepared.wire（B1-B12 后），format `anthropic-messages`，messages=`wire.messages`，headers=sanitized。
- 对齐 legacy pipeline.ts:244（effective）+ adapter onPrepared（wire）。

### 2.6 formatError（S7）+ createResponseAccumulator
- formatError(kind)：`anthropicStreamErrorType` 风格（idle→timeout_error / shutdown→overloaded_error / other→api_error）→ `{event:"error", data:{type:"error", error:{type, message}}}`。但 handler 内联建错误帧（raw message，P2.2-D4），codec.formatError 备用。
- createResponseAccumulator：`createAnthropicStreamAccumulator()`（暴露 `streamError` 控制信号——upstream mid-stream error 是终态 `error` SSE 而非 throw，handler 据此 fail）。

## 3. Strategies（`src/lib/codec/anthropic-strategies.ts`）

`buildAnthropicStrategies({betaProbe, resanitize, originalPayload, model, maxRetries})` → 8 个 env strategy，via `adaptLegacyStrategy` 包：
```
network → token-refresh → effort-learning → body-field → legacy-thinking → unsupported-beta(getProbeCandidates) → deferred-tool → auto-truncate(truncate/resanitize/countTokens)
```
顺序与 legacy `buildAnthropicStrategies` 逐字一致（pipeline.ts:164）。

> **OQ-strat-1（关键）**：`effort-learning` / `unsupported-beta` 有 `onResolved`（成功后 commit 学习到 negotiation cache）。`adaptLegacyStrategy` 已支持 `onResolved`（透传 legacy.onResolved）。driver runExchange 在 transport.send 成功后调 `activeStrategy.onResolved(env)`（driver.ts:151）。**核验**：legacy onResolved 签名 `{payload, prepareHints, attempt}`，adapter 已映射。但 driver 只调**最后接受 retry 的 strategy** 的 onResolved（activeStrategy），legacy pipeline 调 `lastRetryStrategy.onResolved`——语义一致（都是「产生成功 payload 的那个 strategy」）。需测试覆盖 beta 学习往返。

> **OQ-strat-2**：`unsupported-beta` / `effort-learning` 是 learning retry（独立预算 `MAX_LEARNING_RETRIES`）。driver 已支持 `action.learning`（driver.ts:182）。adaptLegacyStrategy 透传 `action.learning`。核验 learning 预算计数等价。

> **OQ-strat-3**：betaProbe `getCandidates()` 依赖 prepareWire 期 `recordOutbound`。driver 流程：每 attempt prepareWire(记录) → send → 失败 → strategy.handle（unsupported-beta 读 candidates）。时序正确（prepareWire 在 send 前，candidates 反映**本次** attempt 出站 betas）。核验：legacy 同时序（adapter onPrepared 在 execute 内、handle 在 execute 后）。

## 4. Transport（`src/lib/transport/anthropic-transport.ts`）

Anthropic 有**专属 client fetch**（非 sendUpstreamHttp），含特殊错误处理：
- HTTPError 带 `response.headers`（Retry-After 解析）+ `responseText` body + 400 `summarizeToolsForDiagnostics`。
- shutdown-caused AbortError → 重写 retryable 529（client.ts:136）。
- 非流式 fold shutdown 进 fetch signal；流式不 fold（guard owns shutdown）。

**方案**：新建 `createUpstreamAnthropicTransport(deps)`，复用 `createAnthropicMessages` 的**发送核**——但 createAnthropicMessages 内部调 prepareAnthropicRequest（v4 中 prepareWire 已做）。故**抽取** createAnthropicMessages 的「纯发送」部分（fetch + 错误处理 + events），与 prepareAnthropicRequest 解耦，transport 调发送核（传已 prepared 的 wire+headers）。
- transport.send(wire, env)：rate-limiter 包 fetch → captureHttpHeaders → !ok throw HTTPError(带 headers+body+diagnostics) → stream ? guardSseIterable(events) : json。
- guardSseIterable 提供与 processAnthropicStream 相同的 StreamShutdownError/StreamClientAbortError（已核验 stream.ts:282）。
- queueWaitMs → env.ctx.addQueueWaitMs。

> **OQ-transport-1（关键）**：抽取 createAnthropicMessages 发送核是**行为保持重构**（影响 legacy 直连 + web_search hops，二者都用 createAnthropicMessages）。方案：抽 `sendAnthropicUpstream({wire, headers, stream, model, clientAbortSignal, headersCapture})`（纯发送+错误），createAnthropicMessages 变成 `prepareAnthropicRequest + onPrepared + sendAnthropicUpstream`，transport 直接调 sendAnthropicUpstream。现有 `anthropic-client.it.test` 守抽取等价（同 P2.4 的 upstream-ws-attempt 抽取范式）。
> **OQ-transport-2**：shutdown→529 在抽取的发送核内（非流式）。流式的 shutdown 由 guardSseIterable 抛 StreamShutdownError。核验两路 shutdown 语义等价 legacy。

## 5. Handler-v4（`src/routes/messages/handler-v4.ts`）

### 5.1 route 前置（在 driver 前）
- 读 body；warmup 拦截（legacy `handleWarmupRequest`）；web_search 拦截（legacy `handleWebSearchCompletion`）——**这两条在 driver 之前，保持 legacy**。
- system-prompt async 注入（`processAnthropicSystem(body.system, resolvedName)`）+ preResolve model（对齐 CC/Responses/Gemini）。
- 建 betaProbe + clientAnthropicBeta（inbound header）。
- 建 codec（注入 betaProbe + clientAnthropicBeta）+ transport + driver（strategies 工厂注入 betaProbe + codec.getTruncateBaseline + resanitize）。
- driver.runRequest → 失败 settle（codec.getContext + fail）/ reject 400。

### 5.2 pipeline-info 记录（Anthropic 专属可观测）
legacy 在 `runInitialSanitizationAndRecord`（初始）+ `onRetry`（重试）记 `setPipelineInfo({preprocessing, sanitization, messageMapping, truncation})` + features。v4：
- **初始**：handler 在 runRequest 后读 `codec.getInitialSanitizationInfo()` + `getPreprocessInfo()` + buildMessageMapping(original, env.body.messages) → setPipelineInfo（同 legacy 条件 gate）。
- **重试**：driver 无 handler onRetry hook。方案：`adaptLegacyStrategy` 的 `onMeta` 透传 action.meta（sanitization/truncateResult/betas）。handler 给 strategies 工厂传 `onMeta` 回调，累积重试 sanitization + 记 setPipelineInfo + features（复用 legacy `recordRetryPipelineState`）。message-mapping 需 newPayload——**OQ-pipeline-1**：onMeta 只给 meta，不给 newPayload。legacy recordRetryPipelineState 用 `newPayload`（retry 后 payload）做 mapping。driver 重试改 env.body；handler 够不到每次 retry 的 env.body。**候选**：① adaptLegacyStrategy 的 onMeta 扩展为 onRetry(newPayload, meta)；② 接受 message-mapping 在重试时退化（仅初始 mapping，重试 mapping 缺失——L2 轻微差异，钉测试）。倾向 ①（小改 adapter，保 L2 等价）。

### 5.3 streaming pump
`streamSSE(c, stream => { stream.onAbort(()=>clientAbort.abort()); pump(...) })`。pump 复用现有函数（processOneStreamEvent/forwardToClient/startForwardedSseHeartbeat/serverToolFilter/toolInputDecoder/toolCallTextRecoverer/checkRepetition），只换流源：
```
acc = createAnthropicStreamAccumulator()
... 建 filter/decoder/recoverer/heartbeat（同 legacy）...
for await (const rawEvent of driver.runResponse(upstream, env)) {
  // 替 processAnthropicStream 的 parse+accumulate（guard 已在 transport）
  if (!rawEvent.data) { yield keepalive }       // processOneStreamEvent({raw, parsed: undefined})
  else if (rawEvent.data === "[DONE]") break
  else { parsed = JSON.parse; accumulate; if (parsed.type==="error") {process; break} }
  await processOneStreamEvent({rawEvent, parsed, ...})
}
... flush recoverer/decoder（同 legacy 604-613）...
setSseEvents + setForwardedResponse + (acc.streamError ? fail : complete)
catch: settleStreamingFailure / 错误帧 + flush（同 legacy 636-683）
finally: heartbeat.stop()
```
> **OQ-pump-1**：legacy `processAnthropicStream` 在 [DONE] / error-event / done 处 break。v4 内联 break 须逐字复现（[DONE] break、error-event break、!data keepalive yield）。`processOneStreamEvent` 不变（byte-critical），只把它的 driver 调用包好。
> **OQ-pump-2**：transport guardSseIterable vs processAnthropicStream guard——二者 idle/shutdown/client 语义须等价（已核验 error 类型同）。但 processAnthropicStream 的 `shutdownSignal` 默认 `getShutdownSignal()`，transport guardSseIterable 也传 getShutdownSignal()。核验 idleTimeoutMs 同源（state.streamIdleTimeout*1000）。

### 5.4 non-streaming
复用 `handleDirectAnthropicNonStreamingResponse`（marker + server-tool-filter + recover + restore-names + decode + setForwardedResponse + complete）——driver.runResponseNonStreaming(upstream) 给 response，handler 调现有函数。truncateResult 从 strategies onMeta 捕获。

## 10. Round-1 对抗 review 裁决（2026-06-17，已亲自核验代码）

第 1 轮 subagent review + 主线复核（读 legacy-strategy-adapter / unsupported-beta-retry / effort-learning / send / http-error / pipeline.ts）裁决如下：

### 10.1 OQ-strat-1 → **重分类为「修复」（CRITICAL，C2 工作项）**
**已核验真实缺陷**：`adaptLegacyStrategy` 的 onResolved 只传 `{payload, prepareHints, attempt}`，**不传 `meta`**（legacy-strategy-adapter.ts:96-99）。但 `unsupported-beta-retry.onResolved({payload, meta})` 读 `meta?.probedBetas`（unsupported-beta-retry.ts:185,191）来把定位到的 betas fixate 进 negotiation cache。driver 路径上 `meta===undefined` → fixation loop no-op → **跨请求 beta 学习静默失效**（laconic `invalid beta flag` 路径）。`ResolvedContext` 本有 `meta?` 字段（pipeline.ts:138），legacy pipeline 正确传（pipeline.ts:266-271），是 adapter 漏了。
- **为何 CC 没暴露**：CC 3 策略（network/token-refresh/auto-truncate）**无一有 onResolved**；driver 单测的 onResolved spy 是无参 `()=>{count++}`，从不查 context。Anthropic 是首个用 onResolved 策略的格式。
- **effort-learning 无 onResolved**（grep 确认空）——它在 handle 内学习（effort-learning-retry.ts），不受影响。仅 unsupported-beta 受损。
- **裁决**：C2 增 adapter 修复——`adaptLegacyStrategy` 每次**被接受的 retry** 记住 `action.meta`，onResolved 时透传为 `ResolvedContext.meta`（并考虑 `attempt: execIndex` 对齐）。**failing-first 测试**：断言经 driver 的 unsupported-beta.onResolved 收到 `meta.probedBetas` 且 fixate 了 cache（不止「fire 了」）。这是最高风险项，独立于 Anthropic 接线，先修 adapter。

### 10.2 OQ-transport-1/2 → **唯一 delta 是 shutdown→529；优选共享 transport 加 hook，不建重复 transport**
**已核验**：`sendUpstreamHttp` 用 `HTTPError.fromResponse`（send.ts:103），后者**已捕获 `response.headers`**（http-error.ts:24）——RFC 关于 headers 的担忧**不成立**，CC core 已覆盖 Retry-After headers + 400 诊断。`sendUpstreamHttp` **唯一缺**的是 shutdown-caused AbortError → 529 重写（client.ts:136-143，grep 确认 send.ts 无 529/isAbortError/overloaded）。
- **裁决**：**不新建近重复的 Anthropic transport**。给共享 `sendUpstreamHttp`（或其 transport 包装）加可选 `rewriteShutdownAbort?: boolean`（或 `shutdownStatus` hook），Anthropic 路径开启→ 非流式 AbortError 在发送核内重写为 529（**在 driver loop 之前**，见 H1）。CC/Responses/Gemini 不开→ 行为不变。一个 transport、一个 529 站点。
- **streaming 的 shutdown**：guardSseIterable 抛 StreamShutdownError（与 processAnthropicStream 同，已核验 stream.ts:282）。

### 10.3 OQ-pipeline-1 → **优选 `sampleRequest` seam，不widen 共享 adapter**
**已核验**：per-retry 的 `env.body` **已经流经** `codec.sampleRequest(wire, current)`（driver.ts:143-147，每 attempt）。CC 无此关切（不记 retry message-mapping）。
- **裁决**：让 Anthropic codec 在 `sampleRequest` 内把「最新 effective messages」存入闭包，handler 读闭包做 message-mapping + setPipelineInfo；**不**给 `adaptLegacyStrategy` 加 Anthropic-only 的 onRetry（保 adapter 格式无关）。retry 的 sanitization stats / truncateResult / probedBetas/strippedBetas 仍走 `onMeta`（adapter 已有），handler 累积记 setPipelineInfo + features（复用 legacy `recordRetryPipelineState` 逻辑）。
- **关联 M1**：`beta-stripped`/`truncated`/`thinking` 的 recordFeature 在 legacy `recordRetryPipelineState` 内（handler.ts:398-406），绑定本 seam——经 onMeta + sampleRequest 闭包重建，不丢。

### 10.4 新增 commit invariant（H1/H2/H3——CC 零参考覆盖的 byte-critical Anthropic 专属行为）
- **H1（非流式 shutdown→529）**：发送核在 driver loop 之前重写（10.2）。**补 L1 测试**：非流式 + shutdown → 529 retryable（driver 路径，现套件无）。
- **H2（终态 error SSE → fail 非 throw）**：upstream mid-stream `error` 事件被 accumulate（设 `acc.streamError`）+ **forward 给客户端** + break；loop 后 `acc.streamError ? fail : complete`（handler.ts:113,118,121,624-635）。CC 无此路径（OpenAI 终态错误是 throw）。**补专测**：终态 error SSE → `reqCtx.fail`，客户端仍收到该帧，无 throw。
- **H3（catch 路径 flush）**：mid-stream 失败时，错误帧**之前**须 flush `toolCallTextRecoverer.flush()` + `toolInputDecoder.flush()`（handler.ts:655-667）——否则半构建的 tool_use 在失败时被静默腰斩（byte-critical）。**显式 invariant + 测试**，非 line-reference。

### 10.5 route-v4 顺序（M2——保「web_search 留 legacy」的字节保证）
**已核验** legacy `handleMessages` 顺序：warmup（pre-everything，handler.ts:134）→ model resolve → system-prompt → **preprocess**（handler.ts:219）→ web_search check（**带 preprocessInfo**，handler.ts:231-234）→ direct。route-v4 **必须逐字复现此序**：warmup → resolve → system-prompt(async) → preprocess → web_search(legacy，带 preprocessInfo) → driver。否则 web_search hop 收到非 preprocessed payload + 不同 preprocessInfo = L1/L2 分歧。
> **注**：这意味着 preprocess（`preprocessAnthropicMessages` + tool-name mapper 构建）在 route-v4 里要在 driver 之前做一部分（为 web_search 的 preprocessInfo）。但 codec.parse 也做 preprocess。**裁决**：route-v4 先 preprocess（为 web_search 判断 + preprocessInfo），若非 web_search 则把 preprocessed messages 作为 driver 的 raw.body，codec.parse **跳过重复 preprocess**（或 codec.parse 接受已 preprocessed 标记）。**OQ-2-1（round-2 重点）**：preprocess 归 route 还是 codec？倾向 route 前置（与 web_search 共享），codec.parse 只做 sanitize（preprocess 已在 raw.body）。

## 11. Round-2 对抗 review 裁决（2026-06-17，已亲自核验代码）

第 2 轮压测 round-1 修复 + 挖新缺口，揪出**两个 CRITICAL 共享 driver 契约缺陷**（影响所有格式，非 Anthropic-local）。已亲自核验。

### 11.1 **【CRITICAL，新】driver 返回 pre-retry env → Anthropic pump 读 stale `tools`**
**已核验**：`driver.runRequest` 返回 `{ok, upstream, env: rewritten}`（driver.ts:110），`rewritten` 是 **S3 出口的 pre-exchange env**；`runExchange` 内部 `current = action.env`（driver.ts:185）但只 `return upstream`（driver.ts:152），**最终 retry 后的 `current` env 从不返回**。`DriverRequestResult.env` = pre-retry env。
- **为何 CC/Gemini/Responses 没暴露**：它们的 pump 只读 `env.body.model`（handler-v4.ts:261，model 不被任何 strategy 改）。Anthropic pump 读 **`anthropicPayload.tools`**（= legacy `effectivePayload.tools`，post-retry）建 recoverer 的 `toolNames`/`toolSchemas`（handler.ts:557-558,1011-1012）。`deferred-tool-retry`（deferred-tool-retry.ts:66,81,100）**改 `tools`**（flip defer_loading）。故 v4 读 `env.body.tools`（pre-retry）→ deferred-tool retry 后 recoverer toolNames **缺注入/un-defer 的工具名** → tool-call-text-recovery 检测错误 → forwarded 流字节差异。
- **裁决（C0 共享 driver 前置，先于 Anthropic 接线）**：`runExchange` 返回 `{upstream, env: current}`（最终 post-retry env）；`runRequest` 返回该 env。**同时修 CC/Gemini/Responses 的潜在 latent bug**（它们恰好只读 model 而无症状，但契约上应见 post-retry env）。**回归测试**：deferred-tool retry → forwarded 流 recoverer 见 un-defer 的工具名。**核验现有 4 格式套件不回归**（它们读 model 不变，post-retry env 的 model 与 pre-retry 同）。

### 11.2 **【CRITICAL，refined】onResolved meta 通道是 driver 契约改动，非 adapter-local；且 onMeta/meta 捕获须 post-budget-gate**
**已核验**：`EnvRetryStrategy.onResolved(env)`（types.ts:125）**仅收 env、无 meta**。driver 调 `activeStrategy.onResolved(current)`（driver.ts:151）只传 env。legacy `lastRetryMeta = action.meta` 在 **budget gate 之后**设（pipeline.ts:368），onResolved 收 `meta: lastRetryMeta`（pipeline.ts:269）。
- **时序 bug**：adapter 的 onResolved/onMeta 若在 `handle` 内捕获 meta（legacy-strategy-adapter.ts:83），那是 **driver budget gate 之前**（driver.ts:165 handle → driver.ts:182 gate）。budget-rejected 的 retry 也会 fire onMeta → handler 记录被丢弃 attempt 的 pipelineInfo/feature → L2 history 多一条 sanitization + 幻象 `truncated`/`beta-stripped`。
- **裁决（C0 共享 driver 前置）**：**env-`RetryAction` 当前无 `.meta` 字段**（types.ts:133，round-3 核验）——adapter 的 legacy `action.meta` 只在 handle 闭包内经 `onMeta` 即时发射（legacy-strategy-adapter.ts:83），从不挂到返回的 env-action 上。故「driver 在 185-186 读 action.meta」**不可实现**。正确机制：**widen env-`RetryAction` 的 retry 变体携带 `meta?: Record<string, unknown>`**——adapter 把 legacy `action.meta` 设到返回的 env-action 上（**不再**在 handle 内即时 `onMeta`）；driver 在**接受 retry 后**（driver.ts:185-186，gate 之后）把 `action.meta` 存 loop-local `activeMeta`，并：① 调 onResolved 时透传（**widen `EnvRetryStrategy.onResolved(env, meta?)`**）；② 把 meta 发给 handler 的 onMeta sink（**仅 post-gate**，budget-rejected retry 不发射）。这样 onMeta/onResolved 的 meta 都只来自被接受的 retry，与 legacy（pipeline.ts:368 post-gate 设 lastRetryMeta）时序一致。
- **failing-first 测试**：用 **interleaved + budget-rejected** retry 序列（非单次接受），断言 unsupported-beta.onResolved 经 driver 收到正确 `meta.probedBetas` 且 fixate cache、budget-rejected retry 不污染 pipelineInfo（无幻象 truncated/beta-stripped）。
- **关联 truncateResult**：legacy 经 onRetry 捕获 truncateResult 喂 marker（流式 + 非流式，handler.ts:284-288）。v4 走同一 onMeta 通道——故 truncateResult 也须 **post-gate** 发射（否则 budget-rejected truncate retry 设幻象 marker）。

### 11.3 **§10.5 / OQ-2-1 更正：两个 preprocess 步骤是 disjoint，无双重 preprocess**
**已核验**（request-rewrites.ts + anthropic/pipeline.ts）：
- `preprocessAnthropicMessages(messages)`（handler.ts:219）= **message-level** dedup-tool-calls + strip-read-tags（A1-A2）。route 在 web_search 判断**之前**做，preprocessInfo 喂 web_search。
- `runAnthropicRequestRewrites(payload, {toolNameMapper})`（handler.ts:329）= **tool-level + sanitize 链**（`preprocessTools` T1-T5 + tool-name T7 + sanitize A3-A9）。**不**含 `preprocessAnthropicMessages`。web_search 用 plain sanitize（无 preprocessTools）。
- **二者 disjoint，无双重 preprocess**。我 RFC §10.5 的「double preprocess」担忧是**误判**。
- **裁决**：route-v4 只跑 **`preprocessAnthropicMessages`**（为 web_search preprocessInfo + message baseline），把 message-preprocessed body 作 `raw.body`；codec **拥有完整 `runAnthropicRequestRewrites`** 不变（**无 skip-flag**，codec 本就不跑 message-level preprocess）。route 的 `preprocessInfo` 经 `raw` 或 codec 工厂参数线程化进 codec，`getPreprocessInfo()` 返回 **route 的** preprocessInfo（不重新派生）。

### 11.4 message-mapping baseline 锚定 + H2 pseudocode 更正
- **message-mapping baseline = `codec.getTruncateBaseline()`**（= preprocessed、pre-initial-sanitize 的 `anthropicPayload` 同一对象），**非** `originalSnapshot`（client-raw、pre-preprocess）。实现须读 `getTruncateBaseline().messages`，否则 mapping 整体偏移。
- **H2 pseudocode 更正**：upstream `error` 帧须由**同一个 `processOneStreamEvent` 调用** forward 给客户端（它和普通帧一样过 recoverer/decoder/filter/forwardToClient），**break 在 forward 之后**（yield-then-break，对齐 stream.ts:118-121）。错误帧恰好 forward 一次。H2 测试断言：客户端收到恰好一个 error 帧 + `ctx.fail` + 无 throw。

### 11.5 shutdown→529 try/catch identity + decideRoute reject
- **§10.2 shutdown→529**：`sendUpstreamHttp`（send.ts:85）**fetch 无 try/catch**，AbortError 现在裸传播。加 `rewriteShutdownAbort` 需**新增 fetch try/catch**。**invariant**：非 Anthropic 路径（flag 未开）catch 默认分支**原样 re-throw 原 AbortError 对象**（保 stack/identity，不破坏现有 abort 分类）；只 `getShutdownSignal().aborted && isAbortError` → 529；**client-disconnect abort 绝不变 529**（对齐 client.ts:136）。
- **decideRoute reject 悬挂 entry**：与 P2.4-D3 同——codec.parse 建 ctx，decideRoute reject，handler throw HTTPError，**中间件 `completeFromHttpStatus(400)` 收尾为 `failed`**（非悬挂；`createFullTestApp` 缺中间件的 harness 才显 pending）。与 CC/Responses/Gemini 一致，**非新问题**。

### 11.6 修订后的 commit 序列（C0 共享 driver 前置）
- **C0（共享 driver 契约，先于一切 Anthropic）**：① runExchange 返回 post-retry env（11.1）；② widen env-`RetryAction.meta` + `EnvRetryStrategy.onResolved(env, meta?)`，adapter 把 legacy action.meta 挂 env-action、driver post-gate 捕获并透传 onResolved + onMeta sink（11.2）。invariant：driver/adapter 单测（interleaved+budget-reject，断言 probedBetas 经 onResolved 到 cache + 无幻象 pipelineInfo）；**现有 4 格式全套件不回归**（round-3 逐字段核验：4 格式 result.env 只读 model/stream/targetEndpoint/ctx，retry 不改这些；onMeta 仅 CC 用 truncateResult、Responses/Gemini 不用）。可独立 revert。
- **C1**：抽 `sendAnthropicUpstream`（含 529 hook，11.5）。invariant：anthropic-client.it + 全 Anthropic 套件绿。
- **C2**：codec + strategies（不接线）。
- **C3**：handler-v4 + route（flag OFF，11.3 顺序）+ 等价测试（H1/H2/H3 专测 + L2 双轨 + pipelineInfo + deferred-tool tools 往返）。

> **关键收获**：RFC-first 在写任何 byte-critical 代码前，揪出**两个影响所有格式的共享 driver 契约 bug**（pre-retry env 返回、onResolved meta 通道）——直接实现极难发现，且会污染已在产的 CC/Responses/Gemini。这验证了「≥1000 行重构先 RFC」纪律。
